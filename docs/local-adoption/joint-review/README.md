## 구현 계약

- 작업 실패·진단 요청·실패 표본은 현재 임대에 묶인 단일 트랜잭션으로 저장한다.
  임대를 잃은 실행은 `stale`이라는 비권위적 반환값만 내고 새 소유자의 상태를
  변경하지 않는다. 이미 성공한 완료 기록은 보존한다.
- 배포 점검의 타임아웃·도구 부재·확인된 Docker 서버 장애는 검수 결과를
  `rejected`로 확정하지 않는다. 실제 실행된 실패의 증거와 거부 상태는 유지한다.
- 상태 점검은 정상/실패/관측 불가를 구분한다. 관측 불가는 실패 횟수를 보존하며
  롤백을 유발하지 않는다. 정상 관측은 0으로 초기화한다. 같은 릴리스·서비스의
  실패 관측이 3회 누적되면 알려진 이전 배포로 롤백한다. 이미지 불일치는
  `degraded`, inspect 실패는 `unknown`이다.
- 게시·병합 전 승격 의도를 영속화한다. 로컬 복구는 정확한 후보 commit/tree와
  깨끗한 작업 트리, 원래의 expected_active를 확인한다. DB 승격·훅 활성화·저널
  완료도 한 트랜잭션이다. 불명확한 원격 효과는 `blocked_remote`로 남긴다.
- 배포 큐는 단일 DB controller 임대, 세대 확인, 단계 전후 갱신을 사용한다.
  최대 3회 시도, 30초·60초 backoff, 1,200초 임대다. 계약 위반은 blocked,
  실행 인프라 예외는 retry, 실제 점검 거부는 rejected로 분리한다.
  작업 이력과 기존 큐 메타데이터를 보존하고 오래된 controller의 완료 쓰기를 거부한다.

## 검증과 한계

최종 Windows 통합 검증은 **658 passed, 7 skipped**, Linux 통합 검증은
**665 passed**다. Ruff와 diff 검사, wheel/sdist 빌드, 새 이미지 CLI 시작도 통과했다.
검증용 PostgreSQL·Redis는 종료했고 데이터 볼륨은 보존했다.

실행 결과와 정확한 후보 파일 해시는 `verification.json`에 기록한다.
원본 검토 응답의 해시는 [review-receipts.json](review-receipts.json)에 있다.
초기 전체 테스트의 네 실패는 기존의 예외/`retry` 기대값과 새로운 `stale` 반환
계약의 차이였다. 상태·체크포인트·진단을 쓰지 않는 검증은 유지하면서 기대값을
수정한 뒤 재검증했다. 이전 로그도 `.runtime/joint-review`에 보존한다.

실제 Git 임시 저장소와 메모리/실제 PostgreSQL에서 병합 전·병합 직후·DB 커밋 중
오류를 주입했다. 이는 실제 GitHub 게시·병합·운영 장애 검증을 대신하지 않는다.
Linux 전체 테스트는 검증 이미지의 의존성과 읽기 전용 최신 소스 마운트를 사용한다.
새 이미지의 패키지 CLI 시작도 별도로 확인하며 실제 모델 canary는 반복하지 않았다.
