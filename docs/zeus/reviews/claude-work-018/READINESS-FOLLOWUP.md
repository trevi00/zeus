# 별도 환경 개선 명세: WSL disposable 서비스 준비 실패

Codex 결정: PR #73의 증거 보존 수정과 별도 변경으로 처리한다. 현재 조사 대상은 `VerificationServices`의 WSL 호스트 포트 준비 기한 실패다. PR #73 네 수정 반영 뒤 Claude의 다음 구현 후보이며 U003 착수 지시가 아니다.

수용 기준:

1. 기존 실패 11회 중 7회의 집계 범위와 세 최신 실패를 고정한다. 같은 실패 지점과 같은 근본 원인을 구분한다.
2. 컨테이너 health, Docker port 매핑, Windows/WSL 각각의 TCP 및 실제 PG/Redis 프로토콜 응답을 같은 시각축에 남긴다. health 정상만으로 호스트 연결 정상이라고 판단하지 않는다. 서비스 시작·포트 발표·이전 프로젝트 teardown 타이밍을 기록한다.
3. 실행 전 고정한 반복 횟수로 단독 시작과 직전 teardown 직후를 비교한다. 모든 시도를 기록하며 초록까지 재시도하지 않는다. 횟수를 초과하려면 추가 측정의 목적을 별도로 기록한다.
4. 측정으로 원인을 좁힌 다음 최소 수정한다. 기한을 늘리거나 실패를 skip 처리하는 것만으로 해결됐다고 판단하지 않는다. 준비 완료는 실제 접속 가능성과 서비스 identity로 결속한다.
5. Windows 정상 경로, WSL 정상 및 유계 실패, 오접속 방지, 자기 프로젝트 teardown을 검증한다. 운영 컨테이너·다른 작업·전역 Docker 설정을 변경하지 않는다. 재부팅/절전/WSL 종료/Docker Desktop 재시작 없이 수행한다.
6. 유료 모델 호출은 필요 없다. 로그에는 비밀을 남기지 않는다. 수정 PR은 관련 이슈를 Refs로 연결하고 병합·종료는 Codex 검토 뒤 판단한다.

완료 판정: 환경 준비 실패의 원인·조치·고정 반복 결과와 남은 불확실성을 독립 검토할 수 있어야 한다. 전후 발생률 차이의 통계적 유의성을 측정 없이 주장하지 않는다.
