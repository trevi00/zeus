## 달라진 것

  심각도(critical → error → warning → info → debug)가 먼저, 같은 심각도에서는 운영/개발/일반
  순이다. 디버깅은 심각도이며 개발/운영 로그에도 존재한다. 감사와 수집 행은 event_id로 합친다.
- 로그, 경보, 격리, 미확정 종료, 수집 영수증, 로컬 스풀 잔여, 실제 operation 결과를 읽기 전용으로
  표시한다. 작업 성공을 전체 운영 성공으로 바꾸지 않는다. 관측 누락/불가/잘림은 정상 0건이 아니다.
- 실제 shadcn/ui 소유 컴포넌트와 Lucide, React/TypeScript/Tailwind로 개요·로그·보고서·디자인 시스템을
  만들었다. 의미별 색 토큰과 간격·모서리·초점 표시를 공유한다. 기존 상세 기능은 `/legacy`에 남는다.
- 보고서는 진입/명시적 재생성 시점을 고정한다. JSON과 인쇄는 같은 객체를 사용한다. 관측 출처가
  없으면 critical_events/건수는 null, 화면은 확인 불가다. 캡처 당시 연결 실패도 보고서에 남는다.
- 프런트엔드 빌드 CI를 별도 workflow로 두었다. 잠금 파일 설치·타입 검사·lint·빌드·추적된 산출물
  일치 검사를 실행한다. 운영에는 Node 서버나 외부 UI CDN이 필요 없다.
