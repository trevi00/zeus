## Fixed implementation contract

1. Small strict JSON manifest `schema: urn:zeus:operation:1`, opaque `id`, 40-hex `base_revision`, `goal: {path, sha256, criterion, rationale}`, `plan: {objective, acceptance_criteria, allowed_paths}`, `budget: {per_host, total}`, `claude: {model, timeout_seconds, max_budget_usd}`. Reject unknown fields, empty or wrong types, booleans as integers, nonfinite numbers, unsafe paths/IDs, missing goal/criteria. Use existing provider validators for limits. Fixed max_executions=2, fixed worker-v1 and restricted=true. JSON is trusted local operator input, not authentication; ceilings explicitly authorize this operation and never reset earlier ledger slots. Credentials/endpoints remain host settings, not manifest fields. Document a complete example and both PowerShell/Bash invocation.
2. Goal relative regular Markdown must exist at base in Git and match sha256 of Git bytes; allowed paths are explicit relative repository paths without traversal/.git. Base is an existing commit. Read Git with argv not shell. Persist manifest digest plus effective repository/runtime/provider-policy identity (safe digests for endpoint/namespace identity if needed). Same ID with changed manifest/context is refused before any call; same completed ID reports saved outcome without calls or new assignment. Do not require current HEAD==base after completion, since main may advance; pinned base must still be addressable.
3. PG `operations` row atomically claims ID as running and records configuration identity/goal binding and a deterministic six-W message_id/correlation. Transactional outbox for initial assignment, never direct publish-before-claim. A competing invocation or running residue is refused without touching the first owner or invoking providers. Interrupted runs stay visible and fail closed; no automatic ownership takeover. Make the initial LocalCycle creation durable consistently; no preexisting same-cycle state may be silently adopted. DB/Redis unavailable means nonzero/no false success; reuse outbox duplicate semantics.
4. Application orchestration (stdlib/inner contracts only) owns the bounded state machine; CLI/adapter wires real services. Reuse LocalCycle.step; at most two executor calls and finite message-only steps, stop on nonprogress/idle, false result, exception, uncertainty or any failure. A wrapper reserves the existing CallBudget immediately before each underlying execute_one/decide_one, using unchanged fixed machine ledger. Never reserve for an idle/stopped/cached status. Settle afterward; settlement failure stops/nonzero and preserves original counted slot. Retain slot IDs in PG operation receipt. Do not additionally double-reserve inside provider. No conductor/release processing.
5. Before review reservation/provider entry, load the exact pending decision and its candidate task from PG, require succeeded worker, matching task/candidate/decision correlation and revision, and an actual PG evidence_inspections row bound to that task id/generation/attempt/source revision (use EvidenceInspections.require_all_checked plus binding). A summary string `all_checked` alone is insufficient. Missing/incomplete/foreign inspection stops operation and reviewer calls remain zero. On worker failure do not proceed just because a subsequent shell command could run. On lead rejection stop, do not diagnose/retry. Final accepted requires actual succeeded accepted lead decision for this candidate and clean required bookkeeping; `awaiting_operator` alone is insufficient.
6. Persist safe terminal operation status/reason_code, budget slots, cycle handoff, task/review identifiers and observed evidence references. CLI run returns 0 only accepted (including cached accepted), nonzero for everything else; stdout JSON excludes DSNs, raw exceptions, prompt/plan/environment values. General/development/operations logs reuse Observer events/executor audit and Collector. Record collection counts/failure; observation/receipt/ledger settlement failure is nonzero, never quietly successful. Do not recursively repair on failure. Status reads PG only, no observer/executor/bus/provider construction, and does not print sensitive manifest/plan. Existing structured artifact evidence remains available locally.
7. Add only PROGRAMDATA to replay's narrow environment allowlist (case handling consistent with Windows mappings); preserve all other exclusions and snapshot/cache digest binding. Existing historical inspections are immutable. Tests demonstrate value participates in new snapshot identity and secrets remain absent; Windows real ssh-keygen creates disposable keys under test temp and succeeds under replay_environment. On other hosts test semantics; do not claim native Windows behavior measured there.
