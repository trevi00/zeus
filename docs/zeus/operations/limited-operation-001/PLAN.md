# 제한 운영 첫 실제 작업

2026-09-16 Codex 확정. 사용자 진행 지시에 따라 실제 저장소의 제한 운영 RUNBOOK.md를 Claude 팀원이 작성하고 Codex가 검토한다.

## 범위와 종료 조건

- 작업 파일: 이 디렉터리의 RUNBOOK.md 하나. 기존 구현·설정·분석 원장은 변경하지 않는다.
- 구현은 Zeus Executor의 Claude 경로로 실행한다. 입력 배정과 결과 모두 실제 Redis Streams를 통과하며 PG가 작업 권위를 가진다.
- Codex 현재 세션이 결과와 diff를 독립 검토하고 실제 GitHub PR을 제출·병합한다. 이 외부 팀장 세션의 검토를 Zeus 내부 모델 검토 완료로 꾸미지 않는다.
- 수정이 필요하면 같은 원장의 후속 작업으로 전달한다. 불필요한 수정 회차를 만들지 않는다.
- 검토 통과·PR 병합·증거 보존 또는 명시적 차단 기록으로 이번 실행을 종료한다. 상시 무인운영 승인은 별도다.

## 호출·운영 제한

Windows 동시 작업 1개, 실제 Claude 호출 최대 2회(초안 1 + 필요한 수정 1), 각 300초·provider 예산 옵션 USD 1. 실제 청구액 보증은 아니다. 기존 호출 원장의 3개 항목을 유지하며 이번 단계의 누적 상한은 5개다. 원장 초기화나 자동 증액은 하지 않는다. 모델은 앞선 파일럿의 명시적 claude-fable-5-1, restricted=true를 작업별 실행 정책에만 적용한다.

일회용 PG/Redis 스택을 사용하고 운영 컨테이너를 변경하지 않는다. 생성한 리소스만 정리한다. 실행 산출물은 내구성 있는 로컬 runtime 디렉터리에 보존하고 공개 요약에는 자격증명을 포함하지 않는다.

## 문서 수용 기준

1. 이 PC의 제한 운영 범위, 역할, 동시성, 호출 한도와 중단 조건을 명확히 쓴다.
2. 실제 구현된 명령·경로와 아직 구현되지 않은 연결을 구분한다. 존재하지 않는 CLI를 만들지 않는다.
3. 입력 Redis→PG 작업→Claude→outbox→Redis 결과→Codex 검토→PR의 증거를 어떻게 확인할지 설명한다.
4. 중복·미확정 실행·증거 누락은 멈추고 조사하며 자동 재호출·자동 증액·전체 삭제를 하지 않는다.
5. 이번 제한 실행과 상시 자동 검토·승격·카나리아 운영을 구분한다. #101/#103 병합을 과거 모든 장애의 원인 확정으로 부르지 않는다.
