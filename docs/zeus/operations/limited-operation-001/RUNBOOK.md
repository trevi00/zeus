# 제한 운영 001 런북

## 범위

- 활성 저장소는 기존 `C:/Users/rudtn/zeus`이다. 새 워크스페이스와 원본 증거는 `D:/workspaces/zeus` 아래에 둔다.
- Zeus Executor가 Claude로 `worker:implementation`을 실행한다.
- 운영자 스크립트(배포된 CLI가 아님)가 six-W 할당을 실제 Redis에 발행하고, PG Workflow로 소비하고, Claude를 실행하고, outbox를 Redis로 flush한 뒤 `lead:improvement`용 결과 또는 통지를 소비한다.
- 일회용 PG/Redis는 동적으로 선택된 포트를 사용한다. compose의 고정 호스트 포트가 아니다.
- 기본 `zeus inspect`/`observe` 명령은 기본 환경을 대상으로 하며 이 일회용 실행을 보지 않는다. 이 런에서는 해당 명령을 사용하지 않는다.
- 검토는 현재 Codex 세션이 외부에서 diff를 검토하고 PR을 생성·병합하는 방식이다. 자동 내부 리뷰어가 아니다.

## 한계

- 동시 태스크 1개.
- 이 단계의 Claude 호출은 최대 2회. 각 호출은 300초, 선언된 USD 1 옵션.
- 기계 원장 누적 상한은 5.
- 직전 호출은 예산 소진으로 종료되었고 자동 재시도는 없다. 이번은 명시적으로 요청된 두 번째이자 마지막 호출이다.
- 자동 증액, 자동 재시작, 전역 정리는 하지 않는다.

## 증거

다음 항목이 증거다.

- 운영자 영수증
- 태스크 ID
- 스트림 ID
- 예약(reservation)
- 후보 리비전
- 저장된 아티팩트

소유한 자원을 폐기하기 전에 아티팩트를 먼저 보존한다. 폐기된 격리 DB에는 살아 있는 대기 운영 태스크가 없다.

## 중단 조건

다음 중 하나가 발생하면 중단한다.

- 중복 실행
- 알 수 없는 종료
- 증거 누락
- 범위 위반
- 예산 소진

1. 태스크 성공
