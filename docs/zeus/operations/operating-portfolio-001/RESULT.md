# Operating portfolio001: 프로젝트 활동 전달이 배포되었습니다

[PR164](https://github.com/trevi00/zeus/pull/164)가 병합되어 `5bab9e82f9fadfaa94728c51a46d0e95a094c16d`로
배포되었습니다. 배포 이후 Zeus를 통해 실제 Claude 구현 1건과 독립 Codex 검토 1건이 수행되었습니다.
포트폴리오 화면은 이제 프로젝트별 활동 상태와, 소유자가 직접 연결한 후속 작업 이력을 함께 보여줍니다.
아래 수치는 모두 **소유자가 제공한 증거 요약**이며, 이 문서를 작성하며 다시 실행한 것이 아닙니다.

```mermaid
flowchart LR
    A[고정된 STATUS 사양] --> B[Fleet 배정]
    B --> C[격리된 Claude 구현]
    C --> D[호스트 증거 재생]
    D --> E[독립 Codex 검토: 수락]
    E --> F[소유자 전체 테스트 · PR164 CI]
    F --> G[병합 · 배포 5bab9e82]
    G --> H[실제 PG · 데스크톱/모바일 확인]
    H --> I[후속 이력 3건 연결 · Fleet 재개]
```

## 무엇이 바뀌었나

기존 `portfolio`가 확장되었습니다. 소유자 전용 불변 링크 `follow_up(원본, 후속, 증거)`와 실패 1건당 한 줄을
갖는 버킷이 추가되어, 과거 실패와 수락된 후속 작업의 관계가 **명시적으로** 기록됩니다. 이름이나 날짜로
자동 추론하지 않습니다. 프로젝트마다 표본 추출 이전의 전체 모집단 기준 활동 수치(진행 중, 배정 대기,
확인 필요, 조치 필요, 연결된 이력, 수락)가 함께 계산됩니다. 실패 기록은 후속 작업이 연결되어도 삭제되지
않고 별도의 접을 수 있는 이력 영역에 남습니다. Fleet 스케줄링과 모델 프롬프트는 건드리지 않았습니다.

## 세 가지 "수락"을 구분합니다

| 구분 | 의미 | 이 전달에서의 상태 |
|---|---|---|
| 작업 수락 | 독립 검토자가 후보 구현 1건을 수락한 것 | 완료 (작업 단위) |
| 소유자 기준 수용 | 프로젝트 기준에 대한 소유자의 수용 기록 | **별개이며 이 전달로 전체 기준이 수용된 것은 아님** |
| 배포된 커밋 | 런타임이 실제로 가리키는 커밋 | `5bab9e82f9fadfaa94728c51a46d0e95a094c16d` |

화면의 활동 라벨(진행 중, 배정 대기, 확인 필요, 조치 필요, 현재 실행 없음, 미착수)은 활동 상태일 뿐,
기준 완료가 아닙니다. 연결(`follow_up`)은 소유자가 기록한 관계일 뿐이며 사건 해결·기준 수용·병합·배포를
뜻하지 않습니다. 진행 중인 프로젝트도 해결되지 않은 과거 실패를 동시에 가질 수 있어 둘 다 표시합니다.

## 한계

- 라이브 조사 자동 디스패치, 자동 병합이나 자동 배포를 수행했다는 주장은 하지 않습니다. 병합과 배포는
  소유자 결정이었습니다.
- 위 테스트·CI·PG·브라우저 확인은 모두 소유자가 실행해 제공한 결과입니다. 이 문서 작성 중 재실행하지
  않았습니다.
- 알 수 없거나 대기·실행 중인 후속 작업은 과거 실패를 해결하지 않습니다. 오래된 수집기 필드가 없으면
  "활동 요약 없음"으로 표시하며, 잘린 표본에서 전체 수치를 추론하지 않습니다.
- 고정된 사양은 [SPEC.md](SPEC.md), 현재 상태와 확장 요청은 [STATUS.md](STATUS.md)에 있습니다.
- 이 전달로 닫히는 이슈는 없으며, 자동으로 이어지는 다음 작업도 없습니다.
