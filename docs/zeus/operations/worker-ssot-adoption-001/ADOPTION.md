# SSOT 우선 워커 지침 흡수 결과

2026-09-17. SPEC.md와 source.json에 따라 baldrix `skills/_common/code-quality.md`(cbb5c3e)의
선별된 형제 구현 탐색·기존 권위 재사용 원칙을 사용자의 SSOT/이관 요구와 결합해 패키지된 worker-v1
문서에 흡수했다. 별도 프로필, 로더, 게이트는 만들지 않았다.

## 변경한 것

- `src/codex_harness/resources/worker-profile-v1.md`에 "Existing authority first" 절 하나를 "Order of
  work" 바로 뒤에 추가했다. 내용은 네 가지다. (1) 새 기능 전에 할당 범위 안에서 권위 있는 정의, 호출자,
  테스트·증거, 관련 형제 구현 한두 개를 찾고, 검색에서 안 나온 것은 부재의 증명이 아니라 미지이므로
  검색 범위와 남은 불확실성을 기록한다. (2) 재사용·개선·이관·정당화된 신규 구현 중 하나를 명시하고,
  기존 메커니즘에 경쟁하는 진실 원천을 두는 대신 개선·이관하되 알려진 결함을 맞추려고 복사하지 않으며,
  실질적 비호환과 가장 작은 일관된 대안을 기록한다. (3) 개선·이관은 호환성, 롤백, 옛 권위의 은퇴를
  명시하고, 일상적 승인된 선택은 진행하되 결과가 큰 제품·권위·범위 선택은 증거 기반 질문 하나로
  리드에게 넘기며 편집마다 승인 루프를 만들지 않는다. (4) 고정 기준을 통과하면 멈추고 무관하거나 사소한
  기회는 후속 메모로 남긴다. 문장은 새로 썼고 상류 텍스트를 복사하지 않았다. 기존 조사, 검증, 명령
  보고, 권한 규칙은 그대로다.
- `src/codex_harness/resources/worker-profile-v1.json`의 `document_sha256`를 기존 정규화(CRLF를
  LF로, UTF-8) 규약으로 다시 계산했고, source.json의 source/path/commit/blob/pinned_sha256/scope/
  disposition 값을 그대로 쓴 출처 항목 하나를 sources 끝에 추가했다. 기존 출처 다섯 항목, 훅 파일과
  다이제스트, permissions, id, version, character_limit, note는 그대로다.
- 문서 길이는 4989자에서 5977자로 늘었고 한도 6000자 안이다.

## 채택한 원칙과 채택하지 않은 것

- 채택: 다른 인스턴스를 설계하기 전에 기존 형제 구현을 살피는 것, 별도의 중복 경로를 만들지 않는 것.
  여기에 사용자의 요구인 정의·호출자·증거 탐색, 미지의 보존, 재사용/개선/이관/신규 처분 명시,
  호환성·롤백·은퇴 계획을 결합해 Zeus 문맥으로 다시 썼다.
- 미채택: 상류의 비공개 사고 수치, 필수 수치 리팩터링 임계값, 일괄 인터페이스/DTO 규칙, 자동 스킬
  게이트, 과거 성과 서술. 상류 코드 실행, 의존성, 텍스트 복사는 없다. 상류 라이선스와 비공개 사고
  링크는 검증하지 않았으므로 출처 배포·라이선스 주장을 하지 않는다.
- 런타임, 로더, 훅, 테스트, 권한은 바꾸지 않았고 새 재시도나 기록기도 없다.

## SSOT 경로

resources/worker-profile-v1.md와 .json -> adapters/worker_profile.load_profile(LF 정규화 UTF-8
다이제스트, 6000자 이하, 불일치 시 거부) -> adapters/claude_cli.py의 runtime.worker_profile 선택 ->
--append-system-prompt와 실행별 훅 -> 기록된 전달. tests/test_worker_profile.py가 로드, 변조 거부,
훅 서브프로세스, 전송 픽스처를 검증한다.

## 한계

- 이 구현 호출 자체는 이전 패키지 프로필로 시작했으므로 새 지침을 사용한 것이 아니며 새 지침 준수를
  주장하지 않는다. 병합 후의 선택부터 수락된 문서를 로드한다.
- 이 작업이 증명하는 것은 문서 구성과 전달 호환성(로드, 변조·크기 거부, 훅 전달)이며 모델 행동의
  개선이 아니다. 지침 전달은 준수의 증거가 아니고, 픽스처는 실제 모델 준수가 아니며, 기존 검토 권한은
  변하지 않는다. 이 산문 변경에 추가 행동 카나리는 요구되지 않는다.
- 워커는 `python -m pytest tests/test_worker_profile.py -q`와 `python -m ruff check .`만 실행했다.
  전체 스위트와 Windows/Linux/통합 CI는 소유자와 CI가 맡는다.
