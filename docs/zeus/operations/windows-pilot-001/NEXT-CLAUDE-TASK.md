# 첫 제한 운영 개선 작업: 실측 러너의 증거 보존·정리

분석·범위·수용 기준: Codex. 구현·테스트·증거·PR: Claude. 관련 #18/#20. 이번 pilot에서 임시 폴더 정리 실패가 다시 관측됐다. 코드·증거를 살펴 원인을 먼저 재현하며 'Windows라서 느림'으로 단정하지 않는다.

범위: scripts/claude_real_call.py와 필요한 최소 adapter, 테스트. 필수 출력 증거를 내구성 있게 보존한 뒤 러너가 만든 임시 Git/worktree 파일만 정리하고 잔여 원인을 기록한다. 전체 분석 원장, 운영 컨테이너, 다른 프로세스의 파일은 변경하지 않는다. 재부팅·전체 임시 폴더 삭제·프로세스 전역 kill 금지.

수용 기준:

1. 실제 임시 Git 저장소/worktree로 Windows 정리 실패를 재현한다. 실패 파일 목록과 원인 타입을 비밀 없이 기록한다. 읽기 전용 Git 파일과 열린 파일을 서로 다른 경우로 검증한다.
2. 테스트 로그·결과·실제 diff/후보 revision을 외부 증거 디렉터리에 보존하고 hash를 읽어 확인한 뒤 scratch를 정리한다. 삭제 후 존재하지 않는 execution_ref만 남는 것을 충분한 재검토 증거로 취급하지 않는다.
3. 최종 resolved path가 러너가 생성한 정확한 임시 root 안임을 확인한다. 파일시스템 링크·경로 이탈은 중단하고 보고한다. 자기 root 안의 읽기 전용 파일은 정책에 맞게 처리하고, 열린 파일은 유계 실패로 보존한다.
4. 정상 실행에서 scratch 제거, 제거 불가 시 잔여 경로·원인·재정리 가능 여부를 사실대로 남긴다. 생성한 컨테이너와 프로세스가 없어야 하며 다른 작업 데이터는 보존한다.
5. Windows/WSL 실제 임시 파일·Git으로 시험한다. 모델 없이 재현·회귀할 수 있는 cleanup을 검증하려고 유료 모델을 반복 호출하지 않는다. 자기보고와 러너 측정을 계속 구분한다.

이 문서는 다음 작업 명세이며 아직 Zeus 큐에 제출된 실행 명령이나 새 모델 호출 한도가 아니다. 실행 배정 시 작업 ID·기준 revision·한도를 별도로 결속한다. PR은 Refs #18 #20만 사용하고 병합·이슈 종료는 Codex에게 맡긴다.
