# Windows 동률 시각의 재시도 테스트 수정

CI `34380908590`은 5개 작업 중 Windows Python 3.12의 테스트 한 개가 실패했습니다.
실패는 `test_bound_budget_cannot_be_raised_after_restart_and_conflict_does_not_starve_other_task`의
충돌 이벤트 개수 예상값 1, 실제값 0이었습니다. 나머지 네 작업은 성공했습니다.

claim의 정렬 규칙은 `(created_at, id)`입니다. 같은 시각이면 UUID 순서가 적용되므로 정상 작업이
먼저 선택되면 아직 방문하지 않은 작업의 충돌 이벤트는 생기지 않습니다. 테스트가 이 동작을
고려하지 않은 것이 원인입니다. 원본 실패 구간과 전체 CI 작업 결과를 보존했습니다.

첫 작업의 생성 시각을 명시적으로 앞서게 하여 이 테스트가 검증하려는 충돌 관측 조건을 고정했습니다.
한도·시도 수·상태·충돌 개수 assertion은 그대로 유지합니다. 같은 시각의 앞/뒤 UUID 두 경우는
별도 테스트에서 계속 검증합니다. 런타임 구현이나 실행 순서 정책을 바꾸지 않았습니다.

실제 Claude 검수는 수정이 타당하며 해당 파일의 다른 동률 시각 가정도 확인했다고 보고했습니다.
실제 PostgreSQL과 메모리 재시도 검증은 **59 passed**입니다. 전체 Windows 테스트 결과는
`full-tests.log`와 `full-tests.json`에 보존합니다.
최종 Windows 전체 결과는 **797 passed, 215 skipped**이며 Ruff도 통과했습니다.

기존 복구 구현 커밋은 `456be22e905287d351b11d175385eea68d1ed48c`이며, 이 후속 변경은
해당 테스트의 조건만 수정합니다. FA-017 전체 인수나 운영 배포 완료를 의미하지 않습니다.
