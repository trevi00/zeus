# Ticket acceptance and recurrence

This change implements local evidence-bound closure, explicit reopen, historical
lifecycle events and separate GitHub state projection. It continues FA-029 and does
not claim that the entire Zeus harness, human enrollment or production rollout is
complete. No production approver key is generated by this feature.

## Authority setup

An operator outside the agent's repository-write authority provisions an immutable
Git commit containing `.zeus/ticket-trust.json`, then configures the deployment's
`ZEUS_TICKET_TRUST_COMMIT` to that full commit. There is no command-line or packet
override. Missing configuration fails closed even if PostgreSQL has an old pin.
The first accepted decision pins the configured commit/hash/scope in PostgreSQL;
later mismatch requires authenticated rotation. Unsigned rotation is unavailable.
Protect deployment configuration and the PostgreSQL authority tables separately
from ordinary workers. A process with unrestricted administrator/database access
is outside this trust boundary. Merely committing a new key to the working branch
does not change enrolled authority.

The policy has exactly these fields (replace the sample principal/key and dates
through the operator's enrollment procedure):

```json
{
  "version": 1,
  "scope": "trevi00/zeus",
  "max_evidence_age_seconds": 3600,
  "signers": [{
    "principal": "owner",
    "role": "human",
    "public_key": "ssh-ed25519 REPLACE_WITH_ENROLLED_PUBLIC_KEY",
    "valid_after": "2026-09-09T00:00:00+00:00",
    "valid_before": "2027-09-09T00:00:00+00:00"
  }],
  "required_signers": ["owner"],
  "required_human_signers": ["owner"],
  "revoked": []
}
```

Keys and principals must be distinct, requirements must be nonempty and enrolled,
required human principals must have the human role, and required/revoked principals
cannot overlap. Evidence age is 60..86400 seconds. Key validity is checked in Python;
signature verification uses [OpenSSH `ssh-keygen -Y verify`](https://man.openbsd.org/ssh-keygen)
with an isolated allowed-signers file and the `zeus-ticket-close-v1` namespace.
OpenSSH 8.2 or later with this operation is required. Windows retains PROGRAMDATA
because the installed OpenSSH otherwise exits 255 without an explanation; HOME and
USERPROFILE point to the temporary verifier directory and no SSH agent is inherited.

Signing proves configured key authority over the packet. It does not independently
prove physical human presence, sufficient test coverage or the truth of every
measurement. The receipt explicitly records this boundary and which human signatures
the pinned policy required. Enrolled approvers must inspect actual scenarios and
measurements. Automated test identities are never reported as real human acceptance.
Authenticated successor-policy rotation and operational human enrollment remain
required before production adoption; an old pinned policy cannot silently rotate.

## Evidence and commands

Each criterion evidence document contains `kind: ticket-criterion-evidence-v1`, the
exact `ticket_id`, integer `revision`, `content_hash`, full merged `solution_commit`,
timezone-aware `observed_at`, `criterion_index`, `outcome: passed` and nonempty
`details` containing the observation. Environment evidence uses
`kind: ticket-environment-v1`, the same binding/time and concrete environment details.
Keep raw measurement data inline in these immutable documents or retain its source
separately for the approver; arbitrary text in details is an attested observation,
not a runner authentication mechanism. Importing evidence alone grants no authority.

```text
zeus ticket evidence TICKET --file criterion.json
zeus ticket evidence TICKET --file environment.json
zeus ticket prepare-close TICKET --file acceptance.json --output packet.json
```

`acceptance.json` has exactly `solution_commit`, `environment_ref`, `reason` and
`criteria`. The criteria list covers every current criterion in order, using zero-based
`index`, `criterion_hash` (Zeus canonical JSON SHA-256 of that criterion text),
`outcome: passed` and nonempty `evidence_refs` of imported artifacts. Preparation
checks all identities and creates a one-hour packet. Evidence cannot predate the
current revision/cycle or exceed the pinned age limit. Each document is bounded to
1 MiB and the unique evidence set to 8 MiB. Failed, skipped, unknown, absent, unrelated
or stale evidence cannot support closure. A signature cannot override those checks.

Approvers inspect the packet and evidence, then sign the exact generated file outside
Zeus; signatures are beside the packet, never inside the bytes being signed:

```text
ssh-keygen -Y sign -f OPERATOR_KEY -n zeus-ticket-close-v1 packet.json
zeus ticket close TICKET --packet packet.json --signature owner=packet.json.sig
zeus ticket sync TICKET --repo trevi00/zeus
```

Supply every required signature in one close invocation. Zeus does not accumulate
partial approvals or sign with the operator's key. A retry of an already-recorded
packet returns `replayed: true, verification: not_repeated`; it creates no new
approval. Once that ticket has entered another cycle, the old packet is rejected.

```text
zeus ticket reopen TICKET --revision 1 --sequence 1 --reason "Observed recurrence"
zeus ticket sync TICKET --repo trevi00/zeus
```

Reopen removes authority, so it is unsigned. It requires the exact source revision,
sequence and state, retains the old decision/evidence, and invalidates old work.
Editing a closed ticket requires reopening first. `ticket show` exposes the current
sequence, lifecycle history and pending/synced/conflict projection status. After a
verified state projection, that transition cannot overwrite a later manual state
change. To explicitly reconcile a new external close while the local ticket is
already open, use `reopen --expected-state open` with the current revision/sequence
and a new reason. The next close always needs fresh cycle-bound evidence/signatures.
This conservative reconciliation starts a new work cycle and intentionally invalidates
in-flight dispatches too; their results are preserved as superseded. A reason may
describe remote divergence rather than a real defect recurrence. If someone reopens
a remotely closed issue, Zeus does not fight that change: explicitly reopen locally
and obtain fresh closure evidence/signatures if it should be closed again.

PostgreSQL closure and GitHub projection are separate commits. A local decision
marks existing links pending; sync writes the state and verifies actual readback.
Late responses, lost acknowledgements and newer local cycles cannot produce a false
successful receipt. A local lease cannot stop an HTTP request already in flight;
the retained observation and next sync reveal/reconcile that race. External manual
state changes never manufacture local acceptance.
Long signature verification renews an already-owned lease between bounded Git/SSH
operations and before remote access. An expired or stolen lease is never revived.
