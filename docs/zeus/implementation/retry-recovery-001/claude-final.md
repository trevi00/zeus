This runs on **both** replay paths (`:133`, `:148`), so losing an unrelated artifact turns an already-committed recovery into a crash instead of returning its receipt — exactly the idempotency `_evidence` protects for operator evidence. 2. **`repair` is never verified end-to-end.** `test_explicit_repair_...` mutates `status`/`error` directly and never re-claims. For the `InvalidExecutionDeadline` case the corruption actually lives in `message['when']['deadline']`; healing depends on the unstated fact that `claim`'s `task.get("execution_deadline", …)` now finds the written key, while `_ceiling:88` reads that same corrupt string and silently forces the operator to pass a deadline.
