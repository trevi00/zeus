# 명시적 실행 복구와 이관

기존 FA-017 / GitHub #18의 후속 구현입니다. 새 이슈를 만들지 않았습니다.
운영 전환이나 FA-017 전체 인수 완료를 뜻하지 않습니다.

## 실행 계약

`zeus execution-recovery prepare`는 현재 작업 하나와 관련 리뷰 상태를 읽어 검토용 JSON을
새 파일로 출력합니다. 이 단계에서는 PostgreSQL 실행 상태를 바꾸지 않습니다.
`apply`는 검토한 상태의 해시, 15분 이내 유효기간, 근거 아티팩트 무결성을 다시 확인하고
복구 상태·이전 상태·접수증·이벤트를 하나의 PostgreSQL 트랜잭션에 저장합니다.

- `migrate`: 과거 시도는 있지만 한도 기록이 없어 차단된 작업에 명시적으로 새 한도를 설정합니다.
- `resume`: 시도 한도나 기한이 소진된 작업에 추가 실행을 허용합니다. 첫 실행 전에 기한이
  끝나 아직 한도가 없는 경우도 포함합니다.
- `repair`: 잘못된 한도 또는 기한 때문에 차단된 작업의 제어 값을 명시적으로 교체합니다.
  손상된 원본은 접수증에 남깁니다.

새 한도는 **이미 사용한 시도까지 포함한 총 상한**이며 누적 시도보다 커야 합니다.
누적 시도와 회고·프로젝트 정보, 원래 메시지와 입력 해시, 과거 시도 결과는 보존합니다.
generation과 복구 순번을 올려 이전 실행자를 차단하며, 실제 다음 claim에서만 시도를 하나 셉니다.
기한을 바꿀 때 원래 메시지를 수정하지 않고 별도 실행 기한을 사용합니다. 기존 기한을 없앨 수는 없습니다.
동일 복구의 재전달은 실행 및 관련 상태가 그대로일 때만 쓰기 없이 반환합니다.

권한 경계는 기존 로컬 취소 명령과 같은 **신뢰된 로컬 OS/DB 접근**입니다. API는 조직의 conductor
역할을 요구하며 CLI는 이 역할을 사용합니다. `--operator`는 감사용 표기이며 인증된 사람 신원이나
암호학적 서명이 아닙니다. 이 명령이 티켓 종료, 사람 인수, 배포 승인을 부여하지 않습니다.

```text
zeus execution-recovery prepare TASK_ID --operation resume --max-attempts 4 --operator OPERATOR --reason REASON --evidence sha256:ARTIFACT_HASH --output recovery.json
zeus execution-recovery apply --packet recovery.json
zeus inspect execution_recoveries
```

기존 기한이 있으면 `--deadline`에 미래의 timezone 포함 ISO 시각도 명시합니다.
근거는 로컬 아티팩트 저장소에 이미 존재해야 합니다. 출력 파일이 있으면 덮어쓰지 않습니다.
복구 후 claim은 저장된 한도를 재사용해야 합니다. 다른 명시적 `max_attempts`를 보내면 충돌로 건너뜁니다.

## 관련 의사결정

`--bucket decisions_pending`의 threshold 리뷰는 원래 계산 결과·수집 실행·근거 파일과 요청의
결속을 검사합니다. 한도 소진으로 실패한 요청은 기존 리뷰를 보존하여 해당 리뷰 대기 상태로 함께 복구합니다.
이미 결과나 요청이 달라졌으면 복구와 재전달을 거절합니다.
다른 의사결정 phase는 아직 관련 상태 복구 처리가 없어 명시적으로 거절합니다.
모든 phase에 대한 처리, clock 변화 처분, 강제 프로세스 종료 및 통지 대조는 남은 FA-017 범위입니다.

## 공동 검수와 검증 범위

파일 오류 처리를 보완했습니다. 단위 입력·오류 주입은 실제 모델 실행이나 사람 인수로 세지 않습니다.
테스트는 실제 PostgreSQL 및 별도 CLI 프로세스 검증과 메모리 단위 검증을 구분합니다.
