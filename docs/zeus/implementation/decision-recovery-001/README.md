# 의사결정 복구의 관련 상태 검증

기존 FA-017 / GitHub #18의 후속 구현입니다. 새로운 이슈를 만들지 않습니다.
전체 운영 인수나 모델 실행 성공을 의미하지 않습니다.

## 구현 범위

- 과거 실패 진단은 task ID·시도 번호·occurrence ID·원본 실패 아티팩트에 결속합니다.
  원래 작업이 이후 재시도되더라도 유효한 과거 진단을 잃지 않습니다. 이미 등록된 occurrence는 재실행하지 않습니다.
- lead/conductor 릴리스 리뷰는 원래 보고서와 성공 결과, 후보, 릴리스 정책과 리뷰, hook,
  재작업 상태를 검증합니다. conductor는 릴리스에 저장된 원래 정책을 사용합니다.
  이미 큐로 전달됐거나 해당 actor의 리뷰가 기록된 릴리스는 복구로 되돌리지 않습니다.
- 감사 리뷰는 기존 audit binding과 현재 평가자, 독립 리뷰·승인 상태를 재검증합니다.
  리뷰 실행 중 새로 생긴 독립 검사 접수증 자체는 원래 감사 근거를 바꾼 것으로 오판하지 않습니다.
- 기존 threshold 리뷰 복구는 유지합니다. 의도적으로 보류된 research_lead/proposal 경로는
  기존 require_dispatch 정책을 그대로 적용하며, 복구 명령으로 승인 권한을 만들지 않습니다.

복구 접수증의 관련 상태를 claim 직전에 확인하고, 달라졌으면 시도 수를 늘리기 전에
`RecoveryContextChanged`로 차단합니다. 결과·효과를 기록하는 각 native 트랜잭션에서도 재검증합니다.
모델이 blocked/inspection_blocked 결과를 내는 경로도 같은 검증을 적용합니다.
원래 검토 대상과 다른 후보·actor·phase의 효과는 거절합니다.

정상적인 상태 변화로 차단됐으나 현재 native 상태가 여전히 실행 가능하면, 기존
`execution-recovery prepare --operation repair`와 `apply`로 명시적인 재검토와 새 복구 기록을
만들 수 있습니다. 릴리스가 이미 큐에 있거나 리뷰가 끝난 경우 등은 이 경로로도 되살릴 수 없습니다.
복구 순번·접수증·이전 generation을 함께 확인하며, 접수증 포인터가 누락돼 검증을 건너뛰지 못하게 합니다.

## 공동 검토 판단

실제 Claude 검토에서 conductor 정책 재계산의 호환성 문제, 관련 상태 변경 후 재복구 경로 누락,
blocked 결과의 입력 결속 누락을 찾아 수정했습니다. 부가 메모는 관련 상태 해시에서 제외했습니다.
다만 재작업 횟수와 거절된 트리는 native 거절 결과 분기에 사용되므로 루트 판단으로 결속을 유지했습니다.
자신의 정상적인 리뷰 저장을 stale로 오판하지 않도록 공통 `_owned`가 아니라 효과 저장 직전에 검증합니다.

승인이나 사람 인수가 아닙니다. 실제 PostgreSQL과 별도 CLI 프로세스 검증은 복구 준비·적용 뒤
새 프로세스가 변경된 릴리스 큐를 보고 시도를 소비하지 않고 차단하는 경로를 실행합니다.
Git·모델·배포를 가짜 성공으로 대체하여 운영 완료를 주장하지 않습니다.
