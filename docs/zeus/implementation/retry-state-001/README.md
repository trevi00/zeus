# 재시도 한도와 실패 재전달의 영속성

기존 FA-017 / GitHub #18 / `ZEUS-3875a025c20d` 개정 1의 첫 구현 단위입니다.
**기존 실행 데이터의 명시적 복구·이관 절차가 구현되기 전에는 운영에 적용할 수 없습니다.**
이 코드의 테스트 통과는 이슈 전체나 시범 운영 준비 완료를 의미하지 않습니다.

Zeus는 이미 실패 분기에서 원래 작업 행을 갱신하여 프로젝트·회고 데이터를 보존하고 있었습니다.
이번에 고친 실제 결함은 재시작한 호출자가 재시도 한도를 바꿀 수 있다는 점과, 이미 저장된
실패의 동일 재전달을 stale로 잘못 처리한다는 점입니다. 새 이슈나 상류 분석 후보는 만들지 않았습니다.

## 변경된 계약

- 작업은 의존 조건을 충족하여 실행 대상으로 평가될 때 한도를 고정합니다. 검수 작업도 같은
  영속 한도를 사용합니다. 이후 인자가 없는 호출은 고정값을 재사용하고, 명시적으로 다른 값을
  요청하면 해당 작업을 건너뛰며 중복 없는 충돌 이벤트를 남깁니다. 다른 작업은 계속 선택할 수 있습니다.
- 양의 정수만 한도·lease 길이로 허용합니다. bool, 분수, NaN/Infinity, 범위를 넘는 lease와
  timezone 없는 호출 시각은 변경 전에 거절합니다. 새 작업의 deadline은 timezone 있는 ISO 시각이어야 합니다.
- 저장된 deadline이나 한도가 손상된 작업은 원인을 기록하고 해당 작업만 차단합니다.
  과거 실행 이력은 있으나 원래 한도가 없는 작업도 `UnverifiedLegacyRetryBudget`으로 차단합니다.
  현재 정책이나 새 호출자의 값을 과거 한도인 것처럼 추정하지 않습니다.
- 실패 요청은 aggregate, 작업 ID, generation, attempt, 원래 lease owner, 오류, 재시도 여부,
  구조화된 근거에 결속됩니다. 상태 변경과 실패 영수증을 하나의 PostgreSQL 트랜잭션에 저장합니다.
  외부 트랜잭션을 사용하는 진단 생성 경로에서도 함께 커밋하거나 함께 취소됩니다.
- 같은 실패의 재전달은 해당 실패 상태가 여전히 현재일 때만 기록 변경 없이 반환합니다.
  이후 claim·취소·만료·소진 상태를 이전 영수증으로 가릴 수 없습니다. 진단 아티팩트도 다시 쓰지 않습니다.
- 새 실패에 구조화된 근거가 없으면 현재 근거는 비우고 이전 시도의 근거는 `attempt_outcomes`에
  남깁니다. 회고 원문 참조와 프로젝트 필드는 보존합니다.

```text
zeus inspect execution_failures
zeus inspect events
```

이는 신뢰된 로컬 실행 경계의 내부 상태 전이입니다. actor 문자열이나 실패 영수증이 사람의
인수 승인, 모델 실행 인증, 배포 권한을 부여하지 않습니다. deadline은 현재 절대 시각으로
검사하며, 시스템 시각이 바뀐 경우의 복구 정책까지 해결한 것은 아닙니다.

## 검수와 실측

- `baseline.json`: 실제 격리 PostgreSQL과 서로 다른 자식 프로세스 4회로 기존 두 결함을 재현했습니다.
  같은 실패 요청을 다시 보내면 stale였고, 다음 프로세스가 한도를 1에서 2로 바꿔 실행을 획득했습니다.
- `verified.json`: 수정 후 실제 자식 프로세스 6회에서 실패 재전달의 멱등성, 한도 변경 거절,
  소진 상태 보존 및 오래된 실패 영수증 거절을 확인했습니다. PG 상태와 실행한 소스 해시를 보존합니다.
  이 프로브는 Workflow API에 실패 입력을 전달하며 실제 모델을 실행하지 않습니다.
- `claude-design.md`, `root-design.md`, `claude-implementation.md`, `claude-final.md`:
  실제 Claude의 독립 검수와 루트의 판단입니다. 대기 중 조기 한도 고정, 손상 데이터의 전체 큐 중단,
  과거 한도 추정, 재전달 시 아티팩트 재쓰기 지적을 수정한 후 현재 구현 단위의 승인을 받았습니다.
- `target-tests.log`: 실제 격리 PG·별도 Python 프로세스 및 메모리/어댑터 단위 검사를 포함하여
  **178 passed, 6 skipped**. 한글 경로의 실제 파일, 프로세스 재시작, 원장/영수증 동시 rollback,
  동일 요청 재전달, 회고·프로젝트 필드 보존, 상태 손상 격리 등을 확인했습니다.
- `windows-full-tests.log`: **763 passed, 180 skipped**. Ruff도 통과했습니다.
  일반 실행에서 제외된 PG 항목은 위의 실제 서비스 검사와 구분합니다.

회고 카운터 3/5와 프로젝트 메타데이터는 보존 계약을 검사하기 위한 입력입니다. 실제 학습 횟수나
경험의 품질을 측정했다고 해석하지 않습니다. 빈 JSON을 파싱하는 자식 프로세스 검사도 설치된
Claude/Codex 모델의 실제 잘못된 출력을 관측한 시험으로 바꾸어 표현하지 않습니다.

## 운영 적용 전에 남은 작업

기존 시도/한도/종료 원인과 근거를 대조하는 이관 및 versioned recovery 전이가 먼저 필요합니다.
차단된 행의 `error`는 차단 원인이므로 이전 실패 원인은 `attempt_outcomes`에서 읽어야 합니다.
상태 문자열만 `retry`로 바꿔도 한도 확인을 우회할 수 없으며, 임의 변경을 복구 절차로 권장하지 않습니다.

시간 변화에 따른 deadline 복구 처분, 한도·시간 소진 뒤 명시적 권한과 사유에 결속된 재개,
종료 통지와 outbox의 중단 후 조정, 태그 누락/잘못된 JSON/빈 출력 전체 입력 행렬,
동일·중첩 프로젝트와 동률 관측의 전체 인수, 강제 종료·재시작을 포함한 Windows/Linux/WSL의
전체 실제 프로세스·PG 검증 및 필요한 사용자 인수는 FA-017에 남아 있습니다.
