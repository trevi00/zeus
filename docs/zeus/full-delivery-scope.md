# Zeus 전체 작업 범위와 완료 조건

사용자는 2026-09-09에 기존 요청 전체를 계속 진행하는지 확인했다. 저장소 생성과 일부 파티션 검토는 중간 결과이며 전체 완료가 아니다. 작업은 독립 `trevi00/zeus`에서 진행한다.

| 작업 | 현재 상태 | 완료 조건 |
|---|---|---|
| 로컬 하네스 전체 분석 | 진행 중 | `.claude`, `harness`, `guardian` 및 필수 설계 정본의 2,736개 추적 경로와 추가 로컬 자산을 목적·호출·설정·실패·검증·Zeus 대응으로 연결하고 미해결을 해소한다. |
| 경험과 기능 흡수 | 전체 분석 이후 구현할 범위가 남음 | 모든 발견에 채택·수정·보류·제외의 근거를 기록하고, 필요한 기능을 Zeus 계약에 맞게 구현·검증한다. 결함과 과거 승인 상태를 승계하지 않는다. |
| 공동 검토 | 일부 실제 Codex·Claude 검토 완료 | 양측이 먼저 독립 검토하고 발견·이견을 같은 티켓 버전과 증거로 비교한다. 구현은 주 Codex가 맡고 변경 후 다시 검증한다. |
| 배포와 플랫폼 | Windows/Linux 개발 CI 통과, Ubuntu WSL2 네이티브 단위·빌드 검증 통과; 운영·설치 후 업데이트·복구 전체 검증 남음 | Windows PowerShell과 Linux/WSL Bash에서 설치·설정·실행·업데이트·복구를 실제로 재현한다. 기존 codex-harness 운영과 자원을 분리한다. |
| 티켓과 자가개선 | 로컬 PostgreSQL–GitHub Issues 15개 연동 완료 | 관측 → 재현 → 티켓 → 검토 → 수정 → 회귀 검증 → 승인된 승격 → 모니터링을 연결한다. 반복 관측을 중복 집계하지 않고 실패·미처리·알림 누락을 추적한다. |
| SDD와 프론트엔드 | 스펙·검토 준비 계층 구현, 전체 흐름 미완료 | 스펙 논의 → 디자인 분석 → 코드 작성 → 자체 검증 → 알파 배포 → QA·증적·사람 승인 → 점진적 라이브 배포 → CS·모니터링을 반복한다. 핵심 사용자 시나리오·인수 기준을 사람이 검토할 수 있어야 한다. |
| 디자인·백엔드·역할별 팀 | 분석·설계와 구현이 남음 | 검토한 백엔드 자산과 디자인 토큰·컴포넌트·스토리북을 연결한다. 스펙·프론트·백엔드·QA/QC·DevOps의 책임, 인계, 증거와 완료 기준을 명시한다. 사용자 표현의 UI 라이브러리 이름은 설계 시 정확한 대상과 버전을 확인한다. |
| 삼성 휴대폰·태블릿 | 사용자가 후속 단계로 미룸 | Device Farm·SDK·MCP·live/interact·REPL·replay와 log-to-scenario를 조사·설계하고 실제 기기 관측을 재현 가능한 E2E 코드로 연결한다. 기기 미준비를 다른 분석·구현의 중단 사유로 삼지 않는다. |
| 모델·토큰 효율 | 역할 정책과 자격 검증이 남음 | Astra가 설계와 최종 검증을 맡고, Sol의 중요 구현을 동등한 검증 조건으로 안정화한 뒤 Terra의 단순 구현으로 확장한다. 모델 이름 변경만으로 자격을 부여하지 않는다. |

금전 흐름과 사용자에게 보이는 핵심 동작은 실제 환경의 기능·인수·E2E 증거로 검증한다. 모킹·문자열 검사·모델의 자기 보고로 실제 검증을 대체하지 않는다. 사용자가 담당해야 하는 시나리오 판단과 최종 인수는 구체적인 화면·동작·증거가 준비된 단계에서 받는다.

진행 원장은 `docs/full-analysis/coverage.json`, `path-ledger.json`, 파티션별 `files.json`/`local-files.json`, `docs/tickets`에 있다. 하나의 파티션이나 CI 성공을 전체 완료로 표시하지 않는다. 추가 gate writer 검토의 도구 중단도 `harness-lib/continuation-status.md`에 미검증으로 남겨 두었다.
