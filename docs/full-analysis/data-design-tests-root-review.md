# DB·API·검증·디자인 및 테스트 012/013 교차 검토

시작 Zeus revision은 `852564f34e738997c19cf4af917450572d029e6c`이다. 이번 새 primary는 58개, 567,915 bytes다. 기존 원장 모두 미검토였음을 `data-design-tests-prior-unreviewed.json`에 보존했다. 지원 90개 기록은 별도 읽기 범위이며 새 primary에 더하지 않는다. 전체 분석·흡수·시범 운영 준비 완료를 뜻하지 않는다.

Root는 각 검토자의 최종 보고서와 파일별 기록을 읽었다. 과거 규칙·시험명·선언 개수와 실제 수행을 구분한다. 각 폴더의 전문/부분 지원 범위, 해시와 남은 호출 경계가 유효하다. 독립 실제 Claude 검토는 root의 9개 primary와 선택한 직접 지원에 한정하며 58개 전체의 Claude 검토로 합산하지 않는다.

마이그레이션 검사기의 실측은 읽기 실패를 빈 범위로 취급하는 성공, V08 계산 오류의 성공, 복합 버전의 충돌 오탐, 모듈별 목록의 덮어쓰기를 확인했다. 일반 중복과 명시 경로 오류를 차단하는 방어도 관측했다. DB/API 템플릿의 추적성·타입·상태 분해는 유지할 후보지만 개수 일치와 코드 생성 선언은 실제 제약·API·사용자 인수를 대체하지 못한다. 적용된 마이그레이션의 불변성과 실제 상태 확인, 무손실 복구가 필요하다. 상세는 root 폴더의 초기 판단·관측·공동 검토 기록에 결속한다.

tests012는 프로세스 종료 실패를 killed로 반영하는 CLI, 제안값을 읽지 않는 ready 파일 승인, UTC를 지역 시간으로 해석하는 집계, soft assertion을 시험 실패로 전파하지 못하는 경계를 추적했다. 익숙한 fixture나 단위 카운트를 실제 모델 결과·업무 완료로 올리지 않아야 한다. 원본 실행은 하지 않았으므로 이 보고서 자체가 재현 증거는 아니다.

tests013은 토큰 삭제 실패도 소비 성공으로 반환하는 경로, 승인과 실제 diff의 미결속, 원장 기록 실패를 무시하는 rollback, 실패 tuple을 무시하는 알림, 순수 함수라는 주석과 숨은 로그 쓰기의 모순을 추적했다. 현재 단일 읽기 preimage 방어·breaker 오류 시 거절·복구용 sidecar는 보존할 후보지만 전체 장애 복구나 권한 검증은 미완료다. 실환경 재현 없이 exploit 또는 운영 장애 확정으로 표시하지 않는다.

디자인 연구는 사용자 인터뷰·흐름·토큰·카피·상태·키보드/보조기술 검토를 제안한다. 역사적 수치와 교육과정, 출시 제품 목록은 우리 사용자의 과업 성공 근거가 아니다. 실제 소비 스킬 및 린터의 경로도 추적했으며 clean Git에서 검사 대상 0개가 OK로 보이는 정적 경계를 찾았다. 실제 화면 대비·Storybook·사람 과업 검증을 했다는 뜻은 아니다. 원문의 수치·법률·표준·버전은 외부 최신 사실로 인증하지 않았다.

Zeus에는 사용자 8단계 SDD를 유지한다. 스펙·시나리오·디자인·코드·시험 정의는 Git에, 실제 시도·증거·승인·배포·사건은 PG에 결속해야 한다. 문서 PASS나 임의 actor 문자열이 실제 사람 인수와 배포 승인을 대신할 수 없다. Astra→Sol→Terra의 위임 역시 동일 과업·환경·실패 사례의 검증 근거가 필요하다. 삼성 휴대폰/태블릿 실기기 작업은 유예한 상태다.

검사 통합 중 최초 root ad-hoc 집계는 지원 기록에서 `bytes`만 기대해 `KeyError: 'bytes'`로 실패했다(tool chunk `eec99b`). tests012가 선언한 `pinned_bytes`를 확인해 읽기 어댑터를 수정했고 당시 primary 58개/지원 88개 원시 blob·byte·SHA 확인을 통과했다(`cc1c34`). Claude 논의에서 직접 지원 2개를 더 읽어 최종 지원은 90개다. 이는 기록 스키마 대조 수정이며 원본 시험 실패나 통과가 아니다. 초기 관측·실패를 숨기지 않는다.

새로운 운영 구현·컨테이너 교체·배포는 수행하지 않았다. 개별 개선 티켓은 합의된 구현과 개정별 실제 인수 증거를 갖출 때 닫는다.
