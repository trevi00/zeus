## 핵심 연결 판단

1. **소비와 스폰 영수증이 합쳐진다.** `l2_driver._arm_role_request`는 소비 게이트 거부 시에도 `_consume_role_request`를 부른다. 실제 소비 함수(1577–1582)는 이유 없이 워터마크만 전진한다. `role_supervisor.tick` 205–214는 이 워터마크를 보고 모든 결과에 `outcome: spawned`를 쓴다. 따라서 차단되어 프로세스를 만들지 않은 요청도 `spawned`가 될 수 있다. 소비 게이트 테스트 85–95는 차단 뒤 소비 호출의 문자열을 확인하지만 supervisor 결과까지 검증하지 않는다. 요청 접수, 정책 거절, 프로세스 시작, 실행 종료, 산출 검증, 사람 인수를 각각 다른 사실로 남겨야 한다.
2. **safe mode는 전체 정지가 아니다.** `cycle` 1438–1453은 스폰 판정 후에도 curator와 노트 보관을 실행한다. 이 두 후처리에는 해당 함수 자체의 safe mode 검사가 없다. `_autoheart_pass`, `_ladder_pass`, `_latency_pass`의 `spawned` 인자는 이번 주기에 새로 스폰했는지만 뜻한다. 이미 살아 있는 세션 때문에 스폰 함수가 0을 반환한 경우에도 후처리가 가능하다. 전역 lease가 모든 쓰기를 보호한다는 등가는 성립하지 않는다.
3. **스폰 시도 기록과 실행 결과가 비원자적이다.** 1858–1876의 lease 획득·멱등키 기록 후, 브리프 구성과 `Popen`이 있다. `Popen` 이후에도 lease 메타, 일일 회계, 요청 워터마크가 별개 쓰기다(1960–1969). 앞에서 죽으면 실행하지 않은 키가 남고, 뒤에서 죽으면 이미 시작한 프로세스와 미갱신 회계가 갈릴 수 있다. `idempotency.once`는 기록을 먼저 한다는 한계를 명시하며, 자체의 읽기와 append는 하나의 임계구역이 아니다. L2의 lease가 다른 모든 호출자를 자동으로 보호하지 않는다.
4. **PG 권위가 Zeus와 반대다.** DBA와 `projection_pg`는 Git JSONL이 정본이고 PG는 재생 가능한 파생물이라고 선언하고 구현한다. Zeus의 AGENTS 계약은 Git 정의, PG 런타임이다. 원본의 파일 lease·워터마크·예산 파일을 그대로 옮겨 PG가 관측만 하도록 만드는 것은 흡수가 아니다. 정의는 Git에 두되 실행 권위·세대·lease·결과 수신은 PG 트랜잭션 경계로 다시 설계해야 한다.
5. **스케줄과 프로세스 반환값은 성공 판정이 아니다.** L2 진입점은 내부 반환 0·1·2를 모두 프로세스 rc 0으로 접는다(2044). DBA compose는 실패를 `|| true`로 삼키고 실행 시간이 끝난 뒤 600초를 잔다. 이는 고정 간격 재시도 루프이지 달력 발생별 영수증이나 누락 보충 계약이 아니다. 읽은 범위에서 L2의 Windows 작업 등록 정본은 확인하지 못했다. 5분 주기는 주석 주장으로 남긴다.

## l2_driver.py

2044행 전체. 역할 요청·자동 장전·tick 사전 판정·lease·회계·토큰·브리프·프로세스 실행·자가개선 후처리가 한 파일에 모인다. 원문이 선언한 과거 수리 횟수와 운용 성공은 현재 증거로 채택하지 않는다.

`_try_arm`은 safe mode, 규칙, 토큰을 확인한다. 활성 규칙이 하나도 없으면 역할 요청 경로도 도달하지 못한다. 역할 파이프라인은 알려진 kind 일부에 매핑되고 미지 kind는 일반 fallback으로 진행한다. 역할별 파일 원장을 만들지만 키에 요청 내용 해시나 큐 세대가 없다. 장전 시도를 먼저 기록하여 실패가 시도 횟수를 소모한다. 원문 중 ‘한 번 실패하면 자동 재시도하지 않는다’는 설명과 실제 3회 제한의 후속 구현을 동일 상태로 묶지 않는다.

새 후보 재개는 필수 stage가 모두 DONE일 때 reset한다. 이전 후보의 일부 stage만 완료된 상태나 SKIPPED가 있는 상태에 새 후보를 어떻게 결합하는지 의미적 독립성은 미해결이다. 완주 시 `_auto_disarm`은 전달된 binding 대신 하위 명령이 현재 binding을 다시 읽을 수 있는 경계를 갖는다. 그 하위 구현은 이번에 읽지 않아 실제 경쟁 재현으로 승격하지 않는다.

스폰 함수는 활성 lease가 있고 PID가 살아 있다고 판정되면 전역 heartbeat를 본다. heartbeat 판독 불능은 신선한 것으로 처리한다. 협업 세션이 대신 갱신할 수 있다는 한계를 원문도 인정한다. PID 검사는 OS 분기 없이 Windows tasklist를 쓴다. Linux/WSL에서 명령이 없으면 예외가 alive로 접혀 죽은 세션을 자동 회수하지 못할 수 있다. 강제 종료도 taskkill과 PID만으로 이루어져 프로세스 생성 신원 검증이 없다. Windows 콘솔 숨김은 별도 OS 분기가 있으나 이것이 실행기 전체의 호스트 이식성을 뜻하지 않는다.

지원 lease 전문은 잠금 하의 획득·heartbeat·회수·메타 갱신과 epoch fence를 제공한다. 그러나 guard는 epoch와 active 상태만 검사한다. 손상 파일은 `_read`에서 absent로 접혀 획득 시 epoch 1로 재시작할 수 있다. driver는 긴 브리프 구성 후 Popen 직전 재검증하지 않고 Popen 뒤 update_meta에서 guard한다. child에 전달되는 env에는 L2 스탬프·블록 캡·깊이 상수가 있으나 이 경로에서 lease 신원을 직접 넘기지는 않는다. hook 측 fencing 전체는 미추적이다.

일일 12회는 로컬 date와 파일 카운트다. 메타 JSON 손상은 0으로 재설정한다. iteration/wall_clock/delegation_budget halt를 새 세션 창으로 재개하므로 전체 목표의 누적 예산과 같지 않다. max-turns 200, block cap 200, autocompact 700000, subagent depth env는 플랫폼이 실제 강제하는지 현재 확인하지 않았다. 실행 인자에 모델 자격 증거나 승인된 모델 revision이 없다. `--dangerously-skip-permissions`는 이 파일의 실제 인자지만 분석자가 실행하지 않았다.

서킷과 latency 판정 자체의 오류는 fail-open이다. token은 expiry 필드만 검사하며 이 파일에서 서명·과업·예산 범위를 증명하지 않는다. NaN/무한대, JSON 타입 이상, 동시 토큰 회수의 유한성·재검증도 없다. 재anchor·handoff·commit 안내 실패에도 스폰한다. 루프 계속 가능성이 안전·승인 충족과 다른 술어라는 점을 Zeus에서 보존해야 한다.

테스트 지원으로 smoke 1–240만 읽었다(전체 403행 중 나머지 미독). 실제 Claude 대신 Python stub가 env를 기록하며 fake home/state와 일시적 token을 만든다. 일부 PID 종료 축은 실제 sleeper 프로세스를 사용한다. 이는 현재 플랫폼 자격·실제 모델·완전한 역할 수신 계약 검증이 아니다. 테스트 실행 및 의존성 전수 검토는 하지 않았다.

## latency_gate.py

200행 전체. health 판독기의 신선도·오염·분해능 결과로 차단 여부를 만든다. 오염된 측정과 분해 불가능한 측정을 무조건 초과로 취급하지 않는 점은 유용하다. 반면 필수 hook 종류의 전체 분모, 입력 revision, probe 실행 영수증을 검증하지 않는다. 건강한 일부 이벤트만 있는 자료에서 ‘전 이벤트 예산 안’이라는 설명이 과도할 수 있다.

지원 health 537–582는 캐시의 `over_budget` 필드를 사용한다. gate 안의 재계산 helper는 운영 판정의 정본이 아니다. 원본 테스트의 읽은 147–230행은 AST 연결과 합성 표본을 검사한다. 현재 프로브의 정확성과 실측 지연을 입증하지 않는다. driver 1776–1788은 이 결과를 직접 소비하며 이번 경로는 validator-ladder 등급을 조회하지 않는다. unknown/stale 및 예외는 통과한다. Zeus의 필수 자격 부재와 성능 관측 부재를 같은 허용 상태로 합치지 말아야 한다.

## lesson_spot.py

286행 전체. 판독기만 보고 lesson 직접 쓰기를 허용하려다 스키마와 write-boundary 계약을 뒤늦게 확인한 수정 이력을 명시한다. 최종 안내는 brain/proposed의 digest와 curator 경유 결정화다. 이 역사는 ‘소비자가 읽을 수 있다’와 ‘작성 권한이 있다’가 별개라는 기계적 교훈이다.

현재 audit은 자체의 단순 frontmatter 파서다. 필수 필드 선언이 있어도 created_by/trust/origin/lifecycle 전체의 필수성 및 값 타입을 일관되게 강제하지 않는다. 스키마 읽기 실패는 빈 enum이 되어 일부 검증을 없애고, 노트가 0개인 audit도 ok가 될 수 있다. created_by 문자열은 작성자 인증이 아니다. digest 파일 개수도 제안 처리·결정화 완료의 증거가 아니다. 원문이 말하는 indexer/domain registry 결함과 curator의 최종 승격 경로는 이번에 해당 구현까지 읽지 않았으므로 역사적 주장/미추적 경계로 남긴다. Zeus에서는 원본 경험 → 격리 제안 → 근거 검사 → 독립 승인 → 결정화의 각 신원을 연결할 후보다.

## note_archive.py

193행 전체. 네 고정 노트 경로의 첫 줄 marker로 ID를 뽑아 별도 notes 디렉터리에 복사하고 색인을 재생성한다. 서로 다른 ID의 보관을 늘리지만 동일 ID의 내용 변경은 덮어쓴다. 실제 gate PASS나 source revision을 확인하지 않아 수정 중인 노트를 재검증된 개정본처럼 보관할 수 있다. 주기 사이 여러 번 덮어쓴 원본을 복구할 수도 없다.

safe_name은 짧은 해시를 붙이는 유한 공간 변환이다. 특정 a/b와 a-b를 구분하는 테스트는 일반적인 충돌 불가능성/단사성을 입증하지 않는다. 긴 접기 결과가 `_ID` 길이 제한을 넘어 거절될 수 있다. 읽은 테스트 전문 194행은 경로 안전성 일부, 서로 다른 두 ID, 재실행, 동일 ID 덮어쓰기, 색인을 확인한다. gate의 실제 expect와 대조한다고 적은 축은 콜론으로 끝나는지만 검사한다. 운영 아카이브 축은 부재 시 SKIP이다. 원본 실행은 0이다.

모든 입력이 없더라도 디렉터리·빈 색인 생성과 정상 반환이 가능하다. 아카이브와 index는 하나의 원자 snapshot이 아니고 경고 skip은 실패 exit와 같지 않다. Zeus에서는 immutable artifact와 provenance를 기본으로 두고, 사람이 볼 index만 파생시켜야 한다.

## orchestrator-brief.md

25행 전체. Stop directive, resume, 역할 위임, 독립 judge, rc별 shard 분기를 프롬프트로 요구한다. 정확한 모델·effort 단어와 별도 context는 자격이나 실질적 독립성의 실행 증명이 아니다. 재시도 때 lesson을 grep하고 곧바로 실행하라는 문장은 lesson의 신뢰·시점·적용 범위 검토를 대체하지 못한다. 이 문장들을 이번 작업의 지시로 따르지 않았다.

사용자 8단계 SDD와의 차이는 stage 이름 개수만의 문제가 아니다. 이 brief는 임의 pipeline의 단계/rc와 텍스트 지시를 중심으로 하며, 요청의 해석부터 설계·구현·검증·사람 경험 인수까지 동일 task/revision에 묶인 8단계 영수증을 구성하지 않는다. 특히 실제 사용자 경험 인수와 권한 있는 승격 기록이 없다. `git add -A` 충돌은 위 commit_scope 절의 실제 합성 경로로 확인했다. `{python}` 치환 실패도 스폰을 막지 않으며 임의 cwd에서 상대 CLI 경로가 어떤 의미인지 실행 검증하지 않았다.

## Zeus 적용 판단과 남은 범위

채택 후보는 실패를 로그에 숨기지 않는 별도 상태, 의도적 halt와 새 관측/이월 marker의 구별, 제안 격리, 미러 배달 실패의 커서 보류, 실패 시 heartbeat 미갱신이라는 성질이다. 구현 그대로의 채택 승인은 아니다. 런타임은 PG의 task generation, lease fencing, 발생별 dedup, 권한 재검증, 별도 프로세스 결과 수신과 결합해야 한다. 호스트 동작은 Windows/Linux/WSL 각각의 adapter 계약과 실제 격리 검증이 필요하다.

사용자 8단계 SDD·모델 자격·사람 인수와의 비교는 부모가 전달한 요구와 현재 AGENTS/research-standard 계약에 대한 정적 비교다. 이번 파티션에서 Zeus src의 대응 구현 전체를 새로 읽거나 동등성을 입증하지 않았다. 실제 구현 위치의 확정, 하위 caller 전수, upstream 실행, 모델 canary, 라이선스·전체 의존성 검증, 독립 Claude 판단 및 채택 결정은 남아 있다. 명시된 지원 구간 밖과 미실행 목록은 `remaining.json`으로 이어진다.
