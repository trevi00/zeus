## Agreed findings and retained guards

1. **Transforms can erase distinctions.** Partial value_map checks only mapped targets, missing collision with passthrough values; prefix stripping can also collapse two inputs. Both returned OK in direct original observations. Explicitly mapping two inputs to one target correctly returns NEEDS_TRANSFORM and must be preserved. Unknown affix options are ignored, allowing a no-op affix to bypass the disjoint identity guard and produce blocking-eligible DRIFT. A declared identity still follows that guard. Configuration shape, allowed keys and final mapping need an explicit contract.
2. **HIGH is not complete extraction.** Java omitted a two-character member and a same-line member while retaining HIGH; returned-field identity was ignored in favor of the first constructor string. Dart treated nonliteral expression identifiers and an unrelated outside-enum call as HIGH values, while mixed inputs omitted unresolved members. Proto omitted maps/options, attributed a nested field to parent and child, and dropped a second package's same short name. A field type change was invisible to tag:name comparison. These are actual parser outputs on synthetic text, not compiled serialization or a current fleet incompatibility finding.
3. **Discovery and extraction require separate denominators.** Fixed source roots and pre-sort traversal caps omit files; per-file regex limitations omit symbols. Do not infer the latter from the former. safe_read catches errors as empty text and replaces invalid UTF-8. Source spans are computed after comment transformation: multiline block removal shifted an observed original line 5 to reported line 3. Package/path/stack identity, supported syntax, failures and omitted inputs are not fully represented.
4. **Ledger self-consistency is narrower than source truth.** The audit recomputes from recorded sets and cannot detect a self-consistent extraction error. It can detect inconsistent status regardless of whether a human or program wrote it. No divergence between the two formulas on valid generated records was demonstrated. Appending malformed JSON caused a prior valid DRIFT seam to disappear from the audit results. A truncated write is a plausible cause, not a crash execution performed here. Returned empty findings therefore do not prove complete inspection.
5. **Blocking policy and authority are distinct.** parity accepts any fidelity except exact LOW and treats all DRIFT as eligible; the ledger validator selects nonempty producer_only; seam_gate defaults to DRIFT/BLOCKED. Existing LOW suppression, COMPUTED fallback, missing-repository BLOCKED and advisory separation are useful. Different external CI policy is not itself a security bypass. Actual company CI, branch protection and graduation eligibility are unverified. The current spec declares seven seams; historical four-seam and disputed routing descriptions are not current fleet measurements.
6. **Output confinement is not enforced by convention.** seam_scan writes under caller-selected state_dir plus unchecked seam_id. events.jsonl appends, parity.md overwrites, and those operations are not atomic. Its default state path does not enforce exclusion from a fleet path. This is source analysis; no escape or live write probe was run.

## Adaptation decisions and unresolved design

Preserve typed per-stack observations, explicit unknown/LOW/NEEDS_TRANSFORM and missing-source states. Require exact source tree, parser/schema version, qualified contract identity, byte spans, discovery and parse denominators, validated transforms and a versioned directional compatibility policy. Git owns definitions; PG owns runtime observations, attempts, corruption state and approvals. Regex-generated HIGH, set equality or unit success cannot authorize human SDD acceptance, model graduation or deployment.

Several suggestions in Claude's discussion are **not automatically accepted implementations**:

- Adding type to tag:name detects that textual change but does not create a protobuf compatibility oracle. Language-specific compiler/descriptor and directional compatibility evidence is still needed.
- Deciding identity solely from the observed mapping image can conflate intentional declared no-op with malformed configuration. Validate the schema first and define declared versus effective transform semantics explicitly.
- Recovering a previous valid ledger line must preserve a corruption/unknown outcome; silent fallback could present stale evidence as current. Zeus should use PG transactional runtime records and expose damaged imports, not silently treat fallback as clean.
- Sorting before a cap resolves that traversal selection issue only; immutable snapshots, environment/dependency identity, concurrent changes and full omitted-input accounting are still required for reproducibility.
- Policies may intentionally differ between advisory triage and directional deployment gates. Share typed evidence and document the relevant authority; do not force one generic boolean to mean every approval.
