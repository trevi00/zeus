## team_watch.py

`_classify` (98–130) treats a word `DONE` in the last 64 bytes as DONE before examining failure markers. Negated prose containing DONE and an old DONE near a subsequent error can therefore overstate completion. It does not join an attempt ID, process exit, expected worker manifest or durable completion receipt. Recent mtime means RUNNING, including future timestamps; it is not a process heartbeat. `_build_layout` discovers workers once, and refresh uses that list: later workers and absent expected workers are invisible. The grid displays at most nine panels, while totals can include more workers. `_all_done` (306–308) requires at least one DONE, so all FAILED does not satisfy the advertised terminal condition. `--once` can return zero for unfinished states when none is classified FAILED. These exit semantics must not become a Zeus promotion gate. Mailbox read errors become zero depth; the effective mailbox implementation remains pending. Rich text rendering and status guesses are useful operator UI concepts, not authoritative state.

## telemetry_report.py

`_ts_to_epoch` (67–74) removes Z and calls local `time.mktime`, misinterpreting UTC according to the host timezone. Offset/millisecond strings fail parsing and are retained by the time filter without a separate unknown-time count; nonempty numeric timestamps raise AttributeError. `_parse_since_arg` accepts negative/nonfinite float values; later integer formatting can fail. `report_hook_latency` builds output only from numeric-duration groups, hiding a hook whose only events have errors and missing durations. Booleans/nonfinite values are not excluded as measurements. `report_evaluator_accuracy` reports verdict distribution, self-score averages, completion/fallback/split statistics, without an independently labeled correctness oracle. Session IDs are accumulated before filtering by time. Skill top-candidate frequency is not actual delivery or consumption evidence (related to FA012). `telemetry_read.iter_events` reads current JSONL only, turns unreadability/missing files into an empty stream, skips broken JSON, and does not require object shape. “All time” is consequently not the full rotated history, and zero is not proof of healthy collection.

The complete original `scripts/tests/test_telemetry_report.py` contains 19 tests. Its timestamp test checks only positive epoch; its cutoff test explicitly tolerates timezone drift and does not assert removal of the old event. These tests have been read, not yet run at this checkpoint. The evaluator-accuracy path imports additional axis-score code that is not exercised by that module and remains unexecuted.

The policy library enforces a locked-value guard, but its ready-flag existence check does not bind evidence content, reviewed proposal hash, registry version or author identity. A no-op before token validation performs no override mutation and is not itself an unauthorized-write finding. Comparison uses the registry default rather than the effective current override. Override YAML, flag deletion and history are not one transaction; history IO failures are swallowed. Adopt typed finite thresholds and versioned, evidence-bound calibration changes only after reviewing the complete calibration callers. No policy writer or live state has been executed here.

## validate_project.py

Discovery recognizes TypeScript frontend and Flutter directories, but `ROUTING` (57 onward) assigns no validators to either. With only those subroots, `run` returns no results and the CLI returns zero. The text message may say no subroots even though discovery found them. `.claude` at the root takes precedence over Java classification and discovery is only one level deep. `_run_validator` (142–174) imports modules in-process, changes global cwd, captures stdout and scans textual markers; it ignores the ordinary return value from `main`. A nonzero returned integer with no FAIL marker can be reported PASS. Nonzero SystemExit is handled, so do not conflate these cases. There is no process timeout/isolation, outer argv is not reset, cached module state can cross subroots, and import-time effects precede the redirected main output. SKIP and no applicable checks are not frontend acceptance. `test_validate_project.py` lines 1–110 are supporting partial reading only; no actual validators were run.

## writeback_inspect.py

The source header/preview says apply is unimplemented, but arm/apply/rollback are implemented. The apply path already hashes and applies hunks against the same captured bytes, fixing the earlier two-read mismatch; preserve credit for this safeguard. Captured-read-to-replace concurrency remains without compare-and-swap or a transaction across target files. Operator pid/sid/absolute-existing-cwd checks establish context shape, not human approval provenance.

Tokens bind proposal ID and joined preimage content hashes, not the reviewed patch hash and canonical target identities. An artifact can change between arm/apply with the same preimages. `writeback_token.consume` reads/checks/unlinks separately, swallows unlink failure, and returns OK; concurrent consumers can both pass. The original comment calling unlink atomic does not make the entire claim atomic. TTL is mutable mtime and is explicitly documented as a freshness discipline, not adversary-proof authorization. This is a concurrency/reproducibility review, not a hostile-token test.

Consumption occurs before UTF-8 decode, hunk application and preimage-sidecar writing, so later failure consumes the authorization without completion. Each replace is atomic locally but multi-file application and audit update are not; compensation attempts can fail. Quarantine-write success is ignored. `mark_applied` failure after mutation returns a reconciliation error; rollback ignores its return and prints success. Rollback parses sidecar paths/lengths without checking the saved bytes against original preimage hashes or requiring the exact audited target set, and can partially restore files without compensation.

Path handling must be stated precisely: `path_denylist` does realpath/normcase and Windows long-path handling for reserved prefixes. Therefore a claim of “no canonicalization anywhere” would be false. However the positive skills allowlist is a regex on the original path, and `Edit.target_path` retains it; it is not a resolved containment check under the configured assets root. CLI target resolution and reserved prefixes use `Path.home()/.claude`, while state helpers honor separate configuration. Complete Windows junction/alias, concurrent mutation, path-delimiter and rollback crash-recovery validation remains pending. No apply/rollback/token/policy mutations were executed.
