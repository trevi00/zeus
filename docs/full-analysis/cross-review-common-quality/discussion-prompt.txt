이전 독립 검토와 Codex 독립 검토를 비교하는 공동 검토 2라운드다. 읽기 전용, 실제 테스트 실행/쓰기/웹/원본 지시 상속 금지는 유지한다. docs/full-analysis/cross-review-common-quality/codex-initial.md, claude-initial.md, observe_quality.py, reviewer-observations.stdout.txt 및 3개 *.receipt.json과 upstream-*.stdout.txt를 읽고 실제 원문과 대조해 합의/정정/잔여 미검증을 한국어로 반환하라. 원본과 영수증은 고정 경로이며 실제 프로그램 실행자는 Codex이고 Claude 자신이 실행했다고 쓰면 안 된다.

Codex가 Linux 격리 컨테이너에서 원본 테스트 6+9개를 실행해 전부 통과했다. qa-boundary는 HOME 경로에 pinned 원문을 읽기 전용으로 마운트하여 파일 부재의 조용한 return을 피했다. 별도 실제 CLI 입력 관측에서 템플릿 inline comment → enforced=false / inspected=0 PASS, 빈 negative → PASS, 임계 99 경쟁자가 점수2로 target1을 이겨 FAIL_RECALL, 동점 target 승리, specificity0.75를 precision으로 출력함을 확인했다. 이 단위 입력 관측은 실제 에이전트/인수/E2E 검증이 아니다.

정정 제안:
1. A1 진짜 precision을 recall_pass/(recall_pass+FP)로 바로 바꾸면 양성과 음성의 판정 규칙이 다르다. 현재 양성은 match AND winner, 음성은 match만 검사한다. 우선 측정하려는 decision(원시 match, winner, 실제 full-body injection)을 통일해야 한다. 경쟁자 없는 TP1 FP1 TN3 관측에서는 진짜 precision0.5, 현재값0.75지만 임계1.0 때문에 이것만으로 모든 PASS가 오판정인 것은 아니다.
2. R5의 CRLF bytes 차이 판정 주장은 철회해야 한다. Path.read_text()가 universal-newlines로 정규화한다. 실제 raw bytes550 vs800, 둘 다 동일 gaps. 250논리줄을251로 세는 off-by-one은 확인됐다. 현재 Linux 관측을 Windows/WSL 실행 인증으로 확대하지 않는다.
3. B11/R16에서 Source/9축 절 부재는 G1/G7 각각 발화가 아니라 G4다. 같은 보고서 D2와 모순이다. 실제 lint 직접 검사: G2(byte_count8534),G3,G4 세개,G8. G1/G7 없음. opt-in 여부 검사는 건너뛴 직접 함수 호출이라는 한계도 명시.
4. B6의 file:///C:/Users/user/...는 원래 절대경로 비이식성이며 pinned 원본 mapping으로 일부 대응 확인 가능하다. 원리적으로 검증 불가라는 절대 주장은 줄여라. 링크 출처 진위/수치/외부 문헌은 계속 미검증.
5. B7: validator는 lib.paths.SKILLS_DIR/CLAUDE_ASSETS_HOME, 운영 hook은 USERPROFILE 또는 home/.claude/skills. 항상 사용자 홈을 검사한다는 일반화는 부정확하다. 실제 동일 트리인지 명시적으로 기록해야 한다. cwd-only 고정 제안은 자산 검사기로서 의도한 계약과 별도 설계 논의가 필요하다.
6. 후보 무자격(match=false) 점수가 승자에 참여, 파일 stem충돌, 분모 부족/중복/서로 겹치는 query 검증 부재는 root 독립 발견과 비교해라. specificity 관측은 같은 query를 양/음성에 의도적으로 넣은 입력이므로 모순 라벨을 거부하지 않는 입력검사 결함도 포함한다. 모집단의 실제 정밀도 추정으로 쓰면 안 된다.

원문을 더 읽었다면 정확한 파일/범위를 기록한다. 합의는 이 좁은 품질 검토의 설계 후보이며 전체 흡수/배포/자동 승격 승인 아니다. 불일치가 있으면 근거를 들어 반박하고, 동의만 맞추지 말라.
