## Package and debate inspection

Its description explicitly moves deterministic convergence to lib.debate_convergence and removes the legacy duplicate. That is a useful single-consumer direction, not proof of the active loop's complete enforcement. `cli.py` is post-hoc inspection, not orchestration. list creates the debate directory; show/last-verdict construct EventStore, which also creates the session directory. EventStore.replay may emit corruption telemetry. Thus inspection is not purely read-only. Missing and empty events share the no-events result. Last verdict is selected by append order/type, without proving it is the latest authoritative convergence decision or independently approved revision.

`debate.py` generates timestamp/random session IDs without collision handling here. Fast-path eligibility checks absence of truthy critic feedback/open_questions, a non-None proposal, and a strict-design keyword. An empty proposal dict can qualify on an architectural topic; the function does not know resume identity, generation or proposal schema. `load_history_snapshots` includes every truthy snapshot from verdict events; despite its docstring, it has no current-generation exclusion. Consumers must establish ordering/dedup/generation validity. Similarity is intentionally only a backup signal and must stay distinct from correctness. EventStore hashes a payload but does not validate hashes on replay or bind actual reviewer process/role/model identity. Its mid-log corruption telemetry is useful, yet damaged tail records are skipped, valid non-object JSON is accepted, and IO/Unicode failures can still propagate despite the never-raises comment.

## Retry and jury

`dispatch_retry.py` has bounded total attempts and useful full-jitter backoff. However it catches BaseException; any classification other than literal permanent is retried, including interrupt/exit signals under external_jury's classifier. Attempt count does not bound provider call duration, total elapsed time or token cost. max_attempts is coerced/clamped at one, not capped above; backoff/jitter inputs have no finite/range checks. Actual cancellation, deadlines and model budgets require a separate contract.

`external_jury.py` parses a JSON object, then accepts a recognized verdict string without validating the Architect schema, required evidence or target revision. `_tally` uses pluralities with a conservative tie-break, not necessarily a majority: 2 approved, 1 conditional, 1 rejected produces approved at agreement .5. Missing/unparseable/failed members do not enter the denominator; a single valid vote can show agreement 1.0 without the configured panel's quorum. Duplicate provider/model/alias identities are not deduplicated. SINGLE stops at the first response even if unparsable and does not itself enforce non-Claude identity. Cross-vendor selection cannot be claimed to eliminate reasoning bias. Invalid verdict value types can also escape tally handling.

The optional retry/breaker path resolves one breaker outcome per acquired dispatch in finally, a useful safeguard. But `_resolve_model` occurs before that try/finally; normal Exception is caught inside routing, while BaseException/property errors are outside its guarantee. Permanent TypeError/ValueError is counted as provider reached/success even if a request fails locally before transport. Legacy is_available is outside the ask exception handler. `call_budget_sec` is reserved/unused; the docstring's max-attempts-bounds-wall-time claim is not enforced by this function. Provider request/model/environment/timeout implementations remain supporting follow-up; no actual provider was invoked.

`jury_advisory.py` has an explicit opt-in and keeps jury payloads out of convergence by contract. commands/harness-debate.md lines 21–93 confirm that advisory seam and a separate deterministic convergence CLI, with verdict authorship still trusted. The advisory returns skipped reasons for ordinary ask exceptions, but members resolution/import and returned-result shaping are outside the try: “NEVER raises” is too broad. Explicit members bypass the default non-Claude candidates, enabled is truthiness-coerced, and any malformed but returned jury may yield skipped=False with no usable consensus. Failed/missing-member identity and quorum need visibility; disagreement should be retained as advisory evidence without silently becoming approval. The command's only-append-if-not-skipped instruction can omit outage/opt-out history.

## Super-session replay

`orchestrator.py` persists a human phase tree before appending the canonical phase event; link_child mutates memory and ignores the atomic sidecar writer's bool before appending child_linked. load_session trusts the sidecar rather than replaying child_linked events. Missing/empty sidecar becomes {}, malformed JSON raises, but valid wrong-shaped JSON is not checked. A malformed latest phase YAML is replaced by a fresh in-progress root instead of preserving an explicit uncertain state. This can diverge from the human mirror and canonical intent. sid paths are not validated or resolved-contained in these entry helpers.

Research dispatch separately calls should_dispatch, record_dispatch and remaining_quota, then records research_dispatched before the caller actually invokes Agent. Review needs the shared dispatch claim and real child-receipt boundary; do not call it successful dispatch evidence. current/bump iteration counts are separate read+append without CAS. list_sessions assumes its first event carries the goal and reverse-scans phase fields that update_phase does not write; older phase values can overwrite newer ones during that reverse loop. It is a summary heuristic, not actual phase completion.

Pane shard merge removes empty/unreadable/all-invalid shards after tolerant reading; OSError and bad JSON can become []. Eligible terminal records are trusted without checking expected pane IDs, actual process exit or shard generation. It appends each row and then unlinks; crash/partial append/unlink failure or simultaneous mergers can duplicate rows. No event ID/dedup/transaction spans append and deletion. It removes each original ts from the payload and the JSONL helper stamps merge time; original event chronology is lost. Replaying by timestamps can reorder old shards relative to later events or same-pane generations. Shard terminal snapshots do not prove acceptance of their artifacts. Upstream tests 725–892 cover happy path shapes, terminal statuses and second merge after successful deletion, not crash-safe exactly-once transfer.

The completion wrapper forwards caller booleans and optional evaluator verdict to lib.completion_gate.decide_completion; the root phase's exit_condition/evidence is not inspected here. Default require_evaluator=False preserves legacy completion. The lib's first 150 lines show blocking-question/escalate guards and required-evaluator behavior; do not say all callers omit evaluation, since Stop-hook wiring is a separate path. Terminal insight logging may duplicate on repeated reads and failures are swallowed. Canonical phase events, sidecar quota, child results, evaluator freshness and acceptance need a unified versioned PG authority.

## Inventory, prompts, verification loop and acknowledgements

`inventory_scan.py` correctly separates machine-local runtime information from committed asset counts, a useful portability improvement. Its asset inventory is still filesystem counts: missing skills root can raise; directory-shaped *.md/*.py entries count as files; nested lib/provider/validator modules are not counted; root skills are absent; direct/namespaced GSD sums are not an identity-deduplicated union and namespaced entries need not be directories. Untracked assets and same-count substitutions escape the claim of committed-input identity. check compares stripped rendered text, not content hashes or functionality. Runtime debate sessions use an events-file predicate, other registered engines count any directory. Import reconfigures stdout unconditionally. Preserve these boundaries when adapting a Zeus inventory.

`prompts.py` JSON-serializes objects but embeds topic/context/file names and JSON in unescaped XML-like delimiters, with no size bound, trust labeling, source hashes or actual role/model qualification. It relies on an externally supplied role file. Prompt text alone does not enforce independent tools, scope or approval. Builder omission of the documented citation/LOCK/advisory features means the caller must supply them; this file alone is not the whole command contract.

`ralph.py` uses a fresh subprocess per validator, rejects missing/nonzero/stdout FAIL and preserves stderr for repair, improving on in-process text-only dispatch. Empty outcomes do not converge. But a zero-exit SKIP or no-check/no-output validator passes; stderr FAIL alone is not inspected. Arbitrary validator names form script paths without registered-name/containment checks. Full env is inherited, no OS sandbox is supplied, timeout handling drops partial output and does not prove descendant termination. Outcome stores only passed and truncated text, not raw rc/timing/input revision/expected checks. check_iteration accepts caller-provided booleans and unchecked iteration bounds; a passing iteration at the cap can converge by design. Fix prompts include untrusted prior lessons/output verbatim with fences and no provenance. Event records further truncate output to 500 chars. ralph_store manually instantiates EventStore via __new__, coupling internal fields; neither that path nor current constructor validates session IDs.

`trigger_summary.py` reads only current telemetry JSONL, silently ignores decoding/JSON/IO failures and assumes object shapes. Pending/ack identity is timestamp, not event ID, so same-second distinct events share identity and out-of-order timestamps use lexicographic comparison. `--json` takes precedence over acknowledgement flags and silently returns a report without executing the requested ack. Arbitrary --ack-ts can be recorded without proving it was displayed/reviewed; missing-ts events cannot be acknowledged by bulk commands. Data/text aggregation is duplicated. Ack persistence and retention await supporting registry reading. Actual human review and repair must not be inferred from cleared pending counts.

## Adoption and remaining

These are engine semantics and bounded supporting traces, not actual operation. Useful patterns include a single convergence consumer, jitter, opt-in disagreement, missing-validator failure, empty-outcome refusal, stderr preservation and separated runtime inventory. Zeus must rebuild their state transitions on PG task/attempt/approval identities, finite deadlines/budgets and actual scenario receipts.
