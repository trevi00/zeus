## Status line and change notification

context-bar.sh preserves useful optional-lock suppression for status and distinguishes an estimated baseline using a tilde. Its model/context inputs are nevertheless unvalidated, max_context may be zero/non-numeric, negative percentages are not bounded, and the 20k baseline is a fixed estimate rather than actual token measurement. Two transcript slurps have no read/size/time bounds. Failed jq/git commands can leave empty values or suppress information rather than produce a typed unavailable state. The Git count excludes untracked files, detached HEAD omits branch status, and FETCH_HEAD is assumed under cwd/.git rather than resolved for a worktree or subdirectory. Local upstream counts plus a timestamp do not prove current remote synchronization. Git/jq/date/stat/bash availability and Windows path conversion need actual platform tests. printf %b can interpret backslash escapes from interpolated display input; this is display/control-sequence handling, not a demonstrated shell execution exploit. Last user text can expose transcript content in the status line; an opt-in/redaction scope is needed before adapting that feature.

file-changed-handler.py normalizes separators for classification but matches broad substrings: .env, CLAUDE.md and dependency basenames can match unrelated names or parent path segments. Output basename uses the unnormalized input, so a Windows path on POSIX can display differently. Notifications deduplicate by label and discard subsequent paths in that category. JSON object/list/string shape and per-file types are not checked; one malformed entry can abandon the complete output through broad exception swallowing. Empty/unrecognized/malformed input all exit0 without structured diagnostic or delivery receipt. Top-level stdin/stdout reconfigure is outside the try and can fail during import under nonstandard streams. Its header declares watchPaths/hookSpecificOutput while the body emits systemMessage only. Whether that is a real host contract violation depends on actual registration/host API, still unread.

## Local hook installation and push verification

install_pre_commit.sh overwrites hooks in repo_root/.git/hooks, without backup or composition of existing hooks. It does not resolve linked-worktree .git files or effective core.hooksPath. CLAUDE_HOME/SCRIPTS are assigned but unused in constructing the installed hooks; the claim that it honors CLAUDE_HOME needs narrowing. Top-level set-e stops ordinary failures, but chmod failure is deliberately ignored and final OK cannot certify executable installation on every platform.

Installed pre-commit skips when a particular tracked runner path is absent, then invokes an unread validator. Installed pre-push applies the same skip, and cd failure explicitly exits0. It tests the current working tree while ignoring pre-push ref input: passing tests are not necessarily tied to the exact revision being pushed. It exports CLAUDE_HOME to the real repository and runs original test runners, whose full effects are not reviewed here; a local hook is not an isolated execution backend. Temporary-log fallback and cleanup lack a trap, and no overall timeout or process-tree lifecycle is enforced here. Runner rc alone controls the push outcome; actual assertion/skip consumption is inside unread runners. Existing failure tail display and two-runner ordering are useful. Source comments about exhausted private Actions minutes are historical rationale, not evidence of current GitHub limits or Zeus configuration.

## Coverage gap and diagram helpers

jacoco-gap.py exits0 when its report is absent. Missing counter metadata becomes (0,0), rendered as OK/100 percent. ALL checks LINE/BRANCH/METHOD while the summary prints more counter types. Summary-only decides on root counters and ignores excludes; detailed mode decides solely on collected method gap rows, after class filtering. Consequently root/class gaps without corresponding method rows can coexist with detailed no-gap output; this is a static input-shape hypothesis pending observation. Excluded classes and missing data are not separate denominators. Duplicate/missing/negative/non-integer counters, unexpected/namespaced XML and report freshness/source identity are not validated. XML parse errors propagate; stdin/stdout reconfigure runs at import. No actual build/test/JaCoCo generation or report authenticity is established by this script.

mermaid-validate.py correctly labels itself basic structural checking rather than rendering validation. Most issues, including unknown type, are WARN and exit0; only empty recognized blocks and read failures make ERROR. Missing/unclosed/unrecognized fences can yield no blocks, which is INFO suppressed in output. An empty directory returns0. PASS counts files that contain issue-free blocks, not individual validated diagrams. Type/arrow/initial marker and bracket scans are heuristics, can count comments or labels, and do not invoke an actual Mermaid parser. Reported line numbers are block-relative and filenames reduced to basenames. Recursive *.md discovery has no explicit unsupported/hidden/symlink/size denominator. No assertion that a particular Mermaid string is officially valid or invalid is made without primary language/parser verification.
