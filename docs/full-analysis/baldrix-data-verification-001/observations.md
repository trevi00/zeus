# 원본 Flyway 충돌 검사기 관측

원본 `tools/check-flyway-collision.sh`를 수정 없이 Bash 5.2.15로 12회 실행했다. 실제 임시 디렉터리·파일과 권한을 사용했고 반환값을 대체하지 않았다. SQL 본문은 실행하지 않았다. Flyway 실행 파일은 이미지에 없으므로 엔진·DB 검증은 0회다.

원시 증거: `attempts/e9c164a6ef4742fbb443d54e2d36389e/`. stdout SHA-256: `cc03691fe8500d27d114c7424192c11b1edf4b4ef52bc36d71bc026d46ea3a13`. 입력 파일명·내용·해시, argv, cwd, stdout/stderr와 종료 코드를 보존했다. 컨테이너는 네트워크 없음, 읽기 전용 원본·루트, 권한 제거, 자원·시간 제한, 임시 저장소만 쓰기를 적용했다. 외부 실행 종료 0, 컨테이너 정리 0, 원본 1,648개 파일 바이트 불변을 확인했다.

| 입력 | 실제 종료 | 관측 |
|---|---:|---|
| V1/V2 | 0 | 정상 대조군, MAX V2/next V3 |
| V1 두 파일 | 1 | 실제 파일 두 개를 표시하며 충돌 차단 |
| V1.1/V1.2 | 1 | 첫 숫자 1로 합쳐 충돌 표시, 해당 파일 목록은 비어 있음 |
| V1_1/V1_2 | 1 | 위와 같은 결과 |
| V01/V1 | 0 | 중복 없음; 이 실행은 Flyway의 동치 판정까지 검증하지 않음 |
| V08 | 0 | stderr에 산술 진법 오류가 발생해도 마지막 성공 출력·종료 0 |
| Vbad | 0 | 숫자 버전 추출 실패를 실패로 처리하지 않음 |
| 빈 폴더 | 0 | 파일 없음 후 중복 없음 |
| 존재하지 않는 명시 경로 | 1 | 경로 오류를 명시적으로 차단하는 대조군 |
| 읽기 권한 없는 폴더에 V1 두 파일 | 0 | 파일 없음으로 보고하고 성공 |
| a 모듈에 vendor 누락, z 모듈은 동일 | 0 | basename 맵이 앞 모듈의 목록을 덮어써 parity OK |
| 단일 모듈 vendor 파일 차이 | 0 | 실제 차이를 WARN으로 표시; 이는 선언된 정책과 일치 |

[Flyway 공식 명명 문서](https://documentation.red-gate.com/fd/versioned-migrations-273973333.html)는 점·밑줄로 나눈 버전을 지원한다고 명시한다. 따라서 복합 버전을 지원하는 일반 Flyway 게이트로 그대로 흡수할 수 없다. 정수만 지원하는 프로젝트 정책이라면 지원 문법과 제외 범위를 명시하고 문법 위반·탐색 실패를 별도 결과로 처리해야 한다.

관측은 이 Linux 이미지와 입력에 한정된다. 원본 테스트 묶음, 실제 Flyway validate/migrate, DB 제약, Windows/WSL, 배포, 복구, 동시 버전 예약, 사람 인수는 검증하지 않았다. 기존 하네스·컨테이너·DB는 변경하지 않았다.
