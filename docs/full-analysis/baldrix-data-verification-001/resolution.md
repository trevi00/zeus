# DB·API·검증 자산 공동 검토 판정

원본 Baldrix `cbb5c3e6c9c4af6f86626474f4d7d62fd8e8a6d2`의 primary 9개, 46,688 bytes를 검토했다. Root의 초기 판단을 저장한 뒤 실제 Claude 독립 결과를 읽고, 별도 논의에서 발견·반례·범위를 대조했다. 원본 Bash 12회 실행과 지원 8개 읽기는 따로 기록한다. 전체 58개 배치의 Claude 검토나 전체 저장소 흡수 승인이 아니다.

실제 Claude session `b585fbe3-f004-48d5-8d4e-cc97c0d95d61`: 독립 검토 578.627초, 논의 229.590초, 모두 종료 0/is_error false. 원문·프롬프트·stderr·사용량·해시를 보존했다. Claude는 Read/Glob/Grep으로 검토했고 원본을 실행하지 않았다. 모델 응답 자체는 구현 또는 사람 승인 권위가 아니다.

서로 확인한 핵심은 다음과 같다.

1. **마이그레이션 사전 검사의 실패 누락**: 읽기 불가 폴더, V08 산술 오류, 여러 모듈의 vendor 목록 덮어쓰기를 실제 Bash로 재현했다. 점/밑줄 버전의 서로 다른 파일을 충돌로 판정하며 파일 목록은 표시하지 않는다. 정상 정수 버전·일반 중복·명시 경로 오류·advisory parity 대조군도 보존했다. [관측](observations.md)과 raw receipt가 근거다.
2. **적용 범위를 명시해야 함**: 원본은 vendor 하위 폴더를 전제로 선언한다. flat layout 지원 누락은 해당 프로젝트에 적용할 때의 호환성·필수 검사 분모 문제다. 정확한 파일명 참조 검색 0건은 동적·외부 호출자 부재의 증명이 아니다. 단일 vendor에서는 parity가 생략되므로 MySQL 템플릿과 다중 vendor 도구가 항상 충돌한다는 초기 주장은 철회했다.
3. **템플릿과 집행 연결**: Claude가 지적한 DB 산출물 명명/후보 경로 차이는 추가 추적 대상으로 남긴다. Root는 OpenAPI 검증기 전문과 reviewer 351–424를 새로 읽어 quoted 경로가 정규식 개수 집계에서 빠지는 경계, 프로젝트 로컬 wrapper 우선 탐색, 출력 문자열 기반 진단을 확인했다. 이 조건부 경로로부터 모든 자동 검증이 없다고 확대하지 않는다. 실제 프로젝트 wrapper·등록·설치·실행 분모는 미완료다.
4. **문서 완료와 인수 완료의 구분**: 미기입 placeholder는 생성 대상이다. DELETE204의 빈 본문은 결함이 아니다. GET 상세 응답·PUT 요청·오류/권한·필수 필드 및 숫자 정밀도는 프로젝트 계약으로 완성하고 실제 서비스에서 검증해야 한다. 코드 생성 명령과 경로/필드 수 일치만으로 행동 일치를 주장할 수 없다.
5. **SDD 검증 근거**: Gate3의 행 번호/파일명 포함 비교, Gate4의 개수와 pair identity 차이, Gate5의 출력 창 누락, 금지어 substring 범위를 정적으로 확인했다. 이 명령들을 실행한 것은 아니다. 5 Gates와 점수의 표를 배포 승인으로 승격하지 않는다. DB 스킬에 MySQL5.7 CHECK 미적용 경고가 이미 있다는 방어를 유지한다.

초기 Claude의 넓은 주장과 정정은 `claude-initial.md` 및 `claude-discussion.md`에 그대로 남겼다. Root가 마지막으로 다음 표현도 정정한다.

- 논의의 `api-spec/README.md:101–102`와 “모든 placeholder 교체” 직접 인용은 확인되지 않는다. README는 79행이다. 또한 README `284–291`은 잘못된 파일 귀속이고 실제 체크리스트는 `openapi-template.yaml:284–291`이다. 템플릿 미완성이라는 판정은 실제 placeholder와 README의 복사·명세 작성 단계에 근거하며, 없는 인용을 근거로 사용하지 않는다.
- “진단 불가능한 오탐”은 과하다. 실제 확인한 사실은 도구가 충돌 파일 목록을 출력하지 않았다는 것이다. 다른 파일 목록으로 분석할 가능성을 배제하지 않는다.
- “Bash 1회 실행”은 버전 조회 또는 컨테이너 관측 묶음 1회와 구분한다. **원본 검사기 실행은 12회**, Bash 버전 조회는 1회다. 일반 중복·경로 오류도 선언과 맞으므로 parity만 유일한 정상 축이라는 표현도 사용하지 않는다.
- 프로세스 트리 종료의 일반 보장은 recorder가 false로 남겼다. 이름을 지정한 컨테이너 정리 성공과 원본 바이트 불변은 실제 확인한 별도 사실이다.
- 지원의 grep 히트 구간은 전문 읽기로 올리지 않는다. Root 지원 원장과 Claude가 주장한 선택 읽기 범위를 합쳐 전체 호출 폐쇄라고 표시하지 않는다.

[외부 1차 자료](platform-references.md)는 Flyway의 지원 버전 형식과 source main의 비교 방식을 설명하지만 선택된 엔진 실행 증거는 아니다. V01/V1은 Bash 반환값만 실측했다. 실제 Flyway validate/migrate, DB 적용·제약·업그레이드·복구, codegen·API 왕복, Windows/WSL, 사용자 핵심 과업·사람 인수는 모두 남아 있다.

**결정은 변형 후보 유지, 채택 승인 보류**다. 추적성 표·정규화 근거·계약 시드·명시적 오류 시나리오·적용된 버전 불변 원칙을 Zeus의 Git 정의와 PG 실행/승인 원장에 맞춰 설계한다. 전체 분석과 승인된 실제 인수 전 원본 도구를 운영 게이트로 그대로 복사하지 않는다. 새 FA-031은 마이그레이션 검사의 지원 문법·대상 분모·오류·실제 DB 인수를 다룬다. 다른 교차 발견은 기존 SDD/검증/자가개선 티켓의 추가 근거다.
