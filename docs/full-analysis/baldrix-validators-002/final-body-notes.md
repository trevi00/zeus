# 24개 전문 독해 완료 시점의 추가 기록

checkpoint-notes.md의 9개 원시 기록은 보존한다. 여기서는 나머지 15개 전문의 독립 판단과 이후 읽은 직접 지원 근거를 기록한다. 원본 실행·테스트·프로브는 0이다. 전문 독해 완료는 전이 의존성·실행 검증·흡수 완료가 아니다.

- test: src/test가 없으면 PASS지만 존재하면서 *Test/Tests/Spec.java가 없으면 FAIL이다. Spec.java는 총 테스트 수에는 포함되지만 Service 대응은 Test/Tests만 인정한다. 패키지 없이 basename으로 연결해 동명이인 테스트가 다른 Service를 덮는다. gradle의 jacoco 문자열은 주석에도 있을 수 있고 build/reports/tests 디렉터리는 비었거나 과거 실행이어도 보고서 생성 PASS를 만든다. 실제 run/revision/테스트 결과·커버리지 숫자를 확인하지 않는다. 파일 IO 무시, Java만의 관례, main None/프로세스 0. 누락 Service는 WARN이다. Zeus 인수 증거 대신 프로젝트 구조 발견 힌트로만 변형한다.
- test_depth: tests/test_*.py를 AST로 보되 FunctionDef만 대상으로 AsyncFunctionDef 테스트를 누락한다. 함수 안 중첩 assert/raise나 docstring의 [FAIL], check/expect/verify 부분 문자열 함수, require_/ensure_/raises/fail 이름을 깊이 증거로 인정한다. 호출 바인딩·도달성·실행 여부를 보지 않아 assert True나 실행하지 않는 내부 함수도 통과할 수 있다. SyntaxError/OSError는 skip한 채 문제 없음 PASS, Unicode 오류는 밖으로 나간다. builtin이어도 WARN만 출력하고 main None이다. 의미 있는 실패 오라클과 전체 테스트 분모를 별도 기록해야 한다.
- mutation_safety: skills 문서의 파괴 패턴 주변 ±10행에 example/migration/WHERE/confirm 등 토큰 하나면 안전 처리한다. 부정문이나 다른 코드 블록의 안전 단어도 실제 대상·승인·가드와 인과관계 없이 면제한다. 문서에 설명한 DELETE FROM 패턴은 실제 목록에서 빠졌고 TRUNCATE TABLE 이외 SQL, PowerShell Remove-Item, 분할 명령은 검출하지 않는다. _should_skip은 root 상대 첫 부분만 보므로 skills 아래 중첩 state/node_modules 배제 의도와 다르다. 파일 없음·읽기 실패 분모는 clean과 섞인다. 기본 WARN, --strict만 FAIL/return1이며 argparse는 현재 프로세스 argv를 읽는다. telemetry 쓰기가 있다. Zeus 권한 검증으로 채택하지 않고 문서 lint로만 변형한다.
- private_content_leak: 닫힌 브랜드 토큰과 명시 버전의 shared 경로만 검색한다. 문서의 java/springboot-* 범위보다 실제 범위가 좁고 대소문자·신규 버전은 누락 가능하다. pointer-ok 부분 문자열 하나가 줄 전체를 면제해 같은 줄 다른 민감 정보도 빠진다. private subtree 부분 문자열 배제와 read 오류 빈 결과는 분모를 숨긴다. 의심 내용 120자 snippet을 출력하고 telemetry에도 기록하므로 유출 검사 자체가 2차 저장 경로다. 일반 비밀 탐지·정책 준수 증명은 아니며 FAIL stdout에도 main None이다. Zeus에는 허용 범위와 비밀 제거를 명시한 검사만 변형 가능하다.
- seam_parity_drift: seam별 마지막 JSONL 한 줄만 읽고 그 줄이 잘못되면 seam 전체를 제외한다. JSON scalar·잘못된 transform 형태는 예외가 가능하고 read OSError도 보호되지 않는다. status BLOCKED면 검사를 모두 생략한다. 같은 기록 안 집합·fidelity로 status를 재계산하므로 입력 집합까지 같이 바꾸면 자기 증명을 막지 못한다. fidelity 누락은 LOW가 아니라는 이유로 충분한 값처럼 취급되고 low-fidelity가 mismatch보다 먼저다. producer-only DRIFT만 potential break로 잡는다. drift_count 기본은 scripts/state/seams, main은 cwd/state/seams로 다르다. advisory 설명과 [FAIL] 출력이 상충하나 main None이다. 실제 producer/consumer 데이터·신선도·서명·운영 상태는 미확인이다.
- spec_roundtrip: spec/test .feature의 ID 집합만 비교한다. step 정의 바인딩·assertion·컴파일·테스트 실행은 확인하지 않아 feature 복사본이나 TODO 본문도 100%가 된다. spec ID가 없으면 문제 없음이고 main은 전부 대응한다는 PASS를 출력할 수 있다. 고정 3개 flat glob은 중첩 feature를 놓치며 parse/read 실패는 누락된다. ID 중복을 집합으로 지워 중복 검증이 안 된다. spec/domain 바로 아래 파일만 자기 복사로 배제하고 바깥 복사본은 인정한다. 프로젝트 발견은 CLAUDE_HOME/.claude/spec를 보므로 spec_bundle의 CLAUDE_HOME/spec와 다르며 일반 cwd도 아니다. main WARN만, 출력 최대12. 지원 testgen 296–305는 정확히 ID 집합 산술이며 spec parser는 잘못된 줄을 skip한다. 지원 test_spec_roundtrip 14–64는 feature만 복사해 100%를 기대한다. Zeus에서는 연결 지표만 허용하고 요구 의미·기존 ID 재사용·retire·nooverwrite export·실제 인수는 별도다.
- stdout_utf8_guard: 전체 소스에 reconfigure와 UTF8 encoding 문자열만 있으면 대응 완료로 처리해 주석·docstring·stderr만 변경·미도달 코드도 면제한다. direct print 인자 AST만 보므로 변수에 담긴 한국어·logging·write·alias·동적 fstring 값은 누락한다. .stdout라는 임의 객체 속성은 subprocess 출력으로 오인 가능하다. validators/lib/__init__는 제외되고 읽기·파싱 skip은 분모에 없다. 자기 stdout.reconfigure도 무조건 호출해 StringIO/pythonw(None) 환경에서 실패할 수 있다. cached registry와 실제 졸업 상태 차이를 별도 확인해야 한다. Win cp949와 Linux UTF8 쓰기 경계 탐지 힌트이며 OS 실행 검증은 0이다.
- subagent_refs: 참조 regex는 최소2글자 이름을 요구해 한 글자 agent를 놓치고 match는 소문자로 정규화하지만 agent stem은 그대로여서 대소문자 불일치가 있다. 파일 존재만으로 해석하며 tools/model 자격·런타임 등록을 확인하지 않는다. agents 없음·비어 있음은 PASS라 전체 참조를 미검사한다. built-in Claude agent 5개는 고정 목록이며 외부 현재 문서 확인은 하지 않았다. template 이름·끝 하이픈 등의 면제, nested skip 디렉터리 판정의 첫 부분 오류가 있다. 읽기 오류 빈 결과, telemetry는 앞50개만 남기며 main None이다. Zeus 모델 자격/위임 권한 승인이 아니라 이름 lint로 변형한다.
- skill_frontmatter: 명세는 any nesting harness-* 금지지만 _check_naming 74–76은 최상위 디렉터리만 검사한다. SKILL.md 형제 문서는 실제로 참조되는지와 관계없이 content module로 면제된다. frontmatter 전체 부재는 모든 subtree FAIL, 개별 필드 없음은 mobile만 FAIL이고 나머지는 WARN 합계와 PASS이다. 검사 총파일 수에는 _pipeline·content module 면제가 포함되어 실제 completeness 분모가 아니다. lib.frontmatter 전문에서 모든 값은 원시 문자열: keywords: []나 description: ''도 nonempty로 통과하고 YAML nesting/list 해석은 없다. Path.as_posix는 실제 Windows Path에 적절하지만 POSIX에서 역슬래시가 든 문자열까지 separator로 바꾸지는 않는다. 파일 glob/stream 예외는 never-raises 계약과 다르다. Zeus 등록 schema/호출 가능성·권한 자격과 분리하여 필드 lint만 변형한다.
- skill_quality_axes: ISO/IEC 25010 9축을 강제한다는 주장은 원문 표준 미확인이고 구현은 문서 형식이다. Source 이후 아무 dash 줄이면 인용, http://만 금지해 URL 자체가 없어도 통과한다. Gotchas 이후 Source 전까지의 모든 ###를 세므로 다른 섹션 소제목을 잘못 합산한다. G7은 축 라벨 문자열 존재만 본다. requires 공백 분할과 skill_index의 모든 md stem/원시 name으로 README·SKILL·자기참조도 대상 존재가 되어 실제 dependency acyclic/callable/호환성을 확인하지 않는다. parser가 YAML lists/quotes를 해석하지 않아 요구 목록과 tech-stack의 통상 YAML 표기는 오판 가능하다. enforce prefix는 문서의 data/infra/ml 외 systems도 포함한다. opt-in 없는 legacy·파싱 실패 legacy는 제외, inspected0에서도 9게이트 PASS이다. - skill_source_liveness: opt-in advisory이고 cron 주1회는 권고일 뿐 이번 범위에서 실제 schedule/실행 영수증은 없다. Source 이후 URL 전부라 다른 섹션도 포함하고 http를 허용한다. 주소/redirect/프록시 경계를 제한하지 않아 원본 문서의 임의 내부 URL도 접속 가능하고 HEAD도 요청 메타데이터를 송신한다. timeout은 요청당10초일 뿐 전체 deadline/최대URL수/전역dedup 없다. read 오류는 main 밖 예외, missing Source/URL은 분모0, 모든 DEAD/NETWORK여도 PASS와0. 검증되지 않은 fallback은 Zeus 신뢰 증거로 제외하고 별도 제한 네트워크 liveness 힌트로만 설계 가능하다.
- skill_staging_isolation: _is_safe는 허용 ROOT 이름 바인딩의 실제 값은 확인하지 않고 Div 오른쪽을 무조건 허용해 절대경로·..를 놓친다. 모든 Attribute/메소드 호출도 같은 루트로 처리해 .parent 체인·with_name/relative_to 같은 이탈 표현까지 안전 판정한다. helper 본문의 return만 검토하며 helper 내부 부작용·nested return·fallthrough None·함수 재바인딩은 모델링하지 않는다. read-only open도 쓰기로 보고 keyword path는 no arg 위반이다. 정해진3파일만 보며 파일 없음/read OSError는 PASS, SyntaxError는 FAIL, Unicode는 예외. 지원 staging_guard 1–83은 resolve/relative_to 실제 경계 검사를 갖지만 자동 interception이 아니라 SHOULD call 계약이고 TOCTOU도 남는다. 실제 detector 194–209/540–623의 write sites는 assert_in_staging 호출 없이 helper 경로를 쓰며 607–610은 AST를 만족시키려고 변수 대신 helper를 전달했다고 명시한다. cid 전체 기원/정규화는 이번 지원 범위 밖이므로 경로 탈출의 실제 exploit 실행으로 주장하지 않는다. tests 48–171은 실패 시 print [FAIL]만 하므로 pytest가 예외로 실패하지 않으며 /tmp/evil 단순 fixture와 문서 false-negative 문자열을 검사할 뿐 위 탈출 경로를 보장하지 않는다. Zeus에는 런타임 파일 권한 경계·정본 승인·후보 비활성화가 필수다.
- subprocess_decode_guard: 부모 디코딩과 자식 stdout 인코딩을 구분하는 문제 정의는 타당하지만 본문 과거실측은 이번 실행 증거가 아니다. subprocess 명명 직접호출/Assign/동일 scope attribute만 보므로 import alias·AnnAssign·with Popen·return run(...).stdout·communicate·closure 바깥 변수 읽기·lambda/class body는 빠진다. 같은 scope 변수 재할당/다른 객체 stdout는 오탐한다. text=True literal만 감지하며 encoding=None이나 잘못된 encoding도 인자 존재만으로 면제한다. errors 인자만으로 텍스트 모드가 되는 경우는 안 본다. SyntaxError/OSError는 skip, Unicode 오류/unguarded reconfigure는 예외. 중요한 직접지원 모순: _blocking은 graduated_names와 VALIDATOR_NAMES 둘 다 요구하지만 lib.graduation.TRACKED는 doc_code_drift/self_model_drift 두 개뿐이고 graduate는 다른 이름을 거부한다. 따라서 pinned 정상 API로 이 검사는 졸업하지 못해 builtin 목록에 있어도 WARN/0이다. tests 38–108은 AST 문자열/트리 검사이며 cp949 실제 자식 프로세스를 실행하지 않는다. Zeus에는 bytes/raw stdout 보존·부모 디코딩 계약·누락 출력 실패 처리와 실제 Windows/Linux/WSL 검증을 함께 적용해야 한다.
- self_model_drift: F-TOOLS는 harness-evaluator 하나의 tools 초과만 검사하며 필수 tool 삭제/빈 tools는 통과한다. parse_tools_field의 list 분기는 실제 minimal frontmatter parser가 list를 내놓지 않으므로 YAML list 보장 아님. F-SCRIPTREF는 backtick의 제한된 python -m/경로만 보고 exists여서 디렉터리·낡은 파일·../탈출 참조도 정상으로 판단 가능하다. 파일 읽기 실패는 누락되고 basename만 보고해 동명 파일 혼동 여지. F-MUTMIRROR의 실제 닫힌 token은6개지만 docstring은5개라 내부 drift 존재. 전체 문서 어느 곳이든 backtick token만 있으면 표의 권한 의미·주체·금지/허용·표 구조가 바뀌어도 clean이다. canonical path는 _HOME.parent/CLAUDE.md로 고정되어 pinned source 밖 parent 문서를 읽을 수 있다. unreadable canonical은 WARN이고 advisory에서는 전체PASS/0. 졸업 상태 오류면 advisory로 낮아지며 import시 registry와 이후state시점 차이도 남는다. selfcheck는 문자열 fixture이며 실행0. Zeus 자가개선 승인·모델 자격에는 exact revision과 명시 권한 계약이 필요하다.
- producer_consumer_coherence: docstring의 모든 dict read/dynamic writer/qualified graph와 실제 구현이 다르다. marker 검사 실제 범위는 marker_keys=tuple/list literal뿐이며 변수 전체를 주면 INFO조차 없이 빠진다. 전역 dict key/setdefault 문자열이 하나라도 있으면 다른 프로젝트/이벤트 producer도 충족시킨다. telemetry는 TELEMETRY_DIR / literal 경로 표현을 read라 간주하고 실제 읽기/쓰기·함수 바인딩은 확인하지 않으며 동명 log_telemetry/const shadowing·미도달 함수도 producer로 인정한다. cron은 reference net에는 있지만 consumer audited5layers에는 없다. caller graph는 qualified symbol이 아닌 전역 Name/Attribute 문자열 집합, public defs setdefault(name)는 동명 정의 중 첫 것만 남긴다. tests만 참조해도 연결되었다고 하고 Markdown은 name 부분문자열과 같은 줄 backtick/괄호만 요구한다. 실제 운영 호출 가능성이 아니라 전역 이름 존재 힌트다. 자기 코드 coherence-ok 이유 문자열만으로 HIGH를 면제하고 expiry/승인자는 없다. SyntaxError/OSError는 누락, Unicode는 예외, --all 없는 MED는 분모 밖. advisory 주장과 main 항상 [FAIL] 출력이 상충하지만 return None/process0. registry의 graduation_scan_drift 분기는 존재하나 TRACKED에는 없어 정상 졸업 미연결이다. tests 20–156은 synthetic 이름 비교와 live HIGH0 기대이며 운영 graph/실행 인수 증거가 아니다.
