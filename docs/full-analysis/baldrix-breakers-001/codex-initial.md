## Composite state and ownership

The state enum, immutable inspection snapshot, per-key history, positive failure threshold, cool-off and explicit result recording are useful. The implementation never selects an alternative model itself; its emitter is caller-provided and defaults to no-op. __init__'s claimed operator visibility therefore depends on actual durable delivery downstream. Composite class explicitly says thread-unsafe and asks callers to supply locks. Atomic JSON replacement prevents partially visible writes but is not a reservation/CAS transaction. Separate hooks or processes are not made safe merely because one hook fire is single-threaded.

try_acquire loads and saves without locking, generation/owner/attempt/nonce. Multiple callers can read OPEN and each reserve the supposedly single HALF_OPEN probe. In HALF_OPEN with probe_in_flight false it returns true without recording a reservation at all. The 120-second reservation TTL reclaims by wall-clock age, not holder death/lease authority. Source provider calls can last180/300 seconds plus retries, so TTL is not proof the old holder has finished. A late old record_success can close a currently reassigned probe; any caller can call record_success/failure without prior acquire. Cancellation and crash recovery need fencing rather than a bool alone.

_save ignores write_json_atomic's return. It can report admitted/OPEN/CLOSED and emit corresponding events while disk state is unchanged. emit_fn exceptions propagate after save (not wrapped); an emitter failure may leave a persisted reservation but no returned admission. Missing/corrupt/unreadable file and invalid state become CLOSED in read_json/_load, mixing unknown with available. Snapshot's bool probe field cannot establish a real running process. OPEN record_failure only changes history; its comment 'extend trip' does not extend cool_off or increment trip_count. First trip is2^1×60=120 seconds, not60.

## Validation and identity

_key_filename replaces slash/backslash but collapses distinct keys and leaves delimiter ambiguity, Windows reserved names/colon/case collisions. project_id is joined without containment; an absolute or parent path can escape base/breakers. These are static API input boundaries, not evidence an untrusted current caller can exploit all of them. No provider alias/model/policy version is bound in the key. external_jury uses raw member.provider, allowing aliases to separate state for the same backend.

_load filters history bool/int but assumes iterable; history None or scalar can raise. Other non-schema history values are dropped or truthified. probe_in_flight uses truthiness. int trip_count accepts strings/bools and has no finite/upper bound (Infinity can raise OverflowError outside catch). timestamps accept NaN/Infinity: NaN cool_off can admit an OPEN probe, NaN reservation age can prevent reclaim. A huge trip_count drives exponentiation before applying the cap. Source/default/invalid/repaired records lack a schema/version and corruption receipt; pending isolation observations will distinguish exact behavior from these hypotheses.

Cross-mode 'newest events' is actually a concatenation of per-mode bool histories in caller iteration order. No event timestamps/IDs exist to reconstruct chronology, and duplicate any_mode_keys can multiply one history. Per-mode trimming can discard history needed for a wider combined window. Truthifying sibling values differs from primary normalization. Secondary rule is disabled when any_mode_keys is absent; that is documented and intentional for the jury's single mode, not automatically a defect.

## Configuration and authority

BreakerThresholds is frozen but not runtime-validated. Minimal YAML parser silently ignores unknown/noninteger values and accepts version without checking it. resolve_thresholds accepts zero/negative integers from the file, with no threshold/window or base/cap relation. Zero window slicing retains the whole history. Reading policy on every result does not preserve the threshold revision of the admitted attempt. Per-instance arbitrary thresholds bypass YAML/override checks entirely.

apply_override validates positive int but bool is an int: true can be serialized as True, then skipped by int parsing on reload while apply_override returned true. Literal TOKEN_SAFE/TOKEN_STRONG strings are direction labels, not authenticated approval receipts. No identity, expiry, exact revision, target or single consumption is bound. Equal-value no-op returns before token check (no mutation); do not mislabel that as an authorized policy change. Policy read/modify/write uses plain file write without locking/atomic replacement or rollback, so concurrent callers may lose updates and partial file reads can change effective defaults. Version, encoding/IO failures and directly edited settings are outside the setter's validation. 'More lenient/safe' direction language for cooldown/window needs an actual semantics/impact review; token names alone do not certify safer behavior.
