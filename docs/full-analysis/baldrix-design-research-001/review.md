## 실제 연결·검사 분모·현행 방어

정확한 `design-research` 경로/7개 파일명을 pinned tree에서 찾는 검색은 결과 0이었다. 이는 숨은 모든 동적 소비자가 없다는 증명이 아니다. 실제 발견한 연결은 각 `_common` 문서의 **dossier 번호 출처 선언**, 디자이너 20–34의 선택적 읽기 지시, critic 18–24의 rubric+린터 지시다. 원문→요약의 자동 생성기/claim ID·버전 결속은 확인하지 않았다. `skill_match.py` 256–308은 skills tree를 수집하며 335–418은 frontmatter·phase/stack·점수·pipeline 가산 후 full-body/top-K/token budget을 적용한다. 따라서 파일이 있다고 매 요청에 모든 규칙이 로드되는 것은 아니다. 실제 hook 등록·로드 순서·프로젝트 설정·주입 결과와 그 이후 출력 구간은 미추적이다.

`design_slop_a11y.py` 1–218은 전문 지원 읽기다. 85–130의 8개 정규식 검사는 줄 단위 img/lang/일반 링크·outline·tabindex·purple gradient·첫 폰트·inline hex tell이다. 렌더링·브라우저 접근성 트리·색 대비 계산·실제 Storybook story·사용자 과업 실행이 없다. `:focus-visible`가 파일 어디에든 있으면 outline 제거 검사를 억제하고(88/106), 태그 regex는 각 줄에서만 적용한다. 링크 regex는 실제 anchor인지 확인하지 않는다. 이런 정적 경계는 미실행 추론이며 새 재현 PASS로 표현하지 않는다.

**검사 분모가 사라질 수 있다.** 21–23의 문서는 Git 변경이 없을 때도 fallback을 말하지만 실제 169–173은 `None`(Git 명령 실패)에만 rglob를 적용한다. clean Git의 `[]`는 0개 스캔 후 198–202의 `[OK]`/0으로 간다. 파일 read 실패는 177–179에서 skip하고 출력에는 스캔 수/skip 수가 없다. fallback은 최대 400개 발견 후 sort라 전체 정렬 뒤의 고정 prefix가 아니며, 제외 디렉터리는 rglob 방문 뒤 검사한다. Git 변경 경로에는 `_SKIP_DIRS` 필터가 없다. 결과는 최대 200개로 잘리며 잘림 표시는 없다. 따라서 0 finding을 전체 파일 clean으로 올릴 수 없다. **기본 lint 성공과 게이트 승인은 다르다.** 190–214는 등록 이름에 포함될 때만 finding→FAIL/1이며 그 외 WARN/0이다. `validators/__init__.py` 33–71 builtin에는 이 이름이 없고 74–84는 외부 graduation state를 동적으로 읽으며 오류는 빈 tuple로 처리한다. `graduation.py` 60의 TRACKED에는 두 다른 validator만 있다. 전체 graduation 구현·실제 state는 읽지 않았으므로 현재 실행 모드를 확정하지 않는다. PR 문구의 기계 finding 0 요구와 advisory 종료값은 별도 계약이다. 프로젝트 cwd에서 `python -m validators...`가 어떤 패키지를 resolve하는지도 실제 설치 없이 보장하지 않는다.

**테스트는 7개 함수의 합성 단위 검사다.** `test_design_slop_a11y.py` 23–73은 문자열·임시 파일로 rule 존재/부재를 검사한다. `test_find_findings_clean_tree_returns_empty_and_exit0`는 `find_findings(root)==[]`만 검사하고 `main()`/exit code를 호출하지 않는다. advisory→blocking 분기, clean Git zero-target, 400/200 cap, unreadable file, 다중행 태그, 실제 화면/AT는 이 파일의 오라클이 아니다. 76–102에 현재 callable main이 있고 AssertionError뿐 아니라 일반 Exception도 실패로 집계한다. 79–81의 과거 7개 SKIP를 현재 main 부재로 단정하지 않는다. `run_units.py` 읽은 범위의 수집은 validator registry 이름을 제외하고 fixture signature가 없으면 main subprocess 경로를 사용하므로, 현재 이 테스트의 default 경로 후보는 main이다. runner의 모든 격리 helper와 실제 호출은 미실행이다. 테스트 선언 7개≠7 PASS다.

**Storybook·독립성·승인도 따로 남는다.** React 스킬 1–54/177–195는 shadcn/Tailwind/Motion/Lucide·토큰·스크린샷 지시를 제공하지만 이 구간에서 story 목록/실제 build config/브라우저 matrix/인수 evidence schema는 확인하지 못했다. `kha-doc-writer.md` 570–573의 Storybook 항목은 문서 배치에 영향이 없다고만 설명한다. 이것을 Storybook 구현 또는 전체 저장소에 Storybook이 전혀 없다는 결론으로 쓰지 않는다. critic은 read-only·독립 역할을 요구하고 실행 URL이 없으면 낮은 확신을 표기한다. 반면 gate 문구는 inline fallback과 관례적 카피/필드 변경 skip을 허용한다. 승인자 신원 분리·대상 변경 후 stale 승인 무효화·금전 카피의 위험 분류를 별도 확인해야 한다.

이는 Zeus에 이미 구현되어 있다는 설명이 아니다. Git은 고정된 spec·scenario·디자인 정의/테스트 코드의 정본, PG는 실행·증거·승인·배포 상태의 정본이라는 사용자 요구에 맞춰 별도 설계·구현·검증할 후보다. 선언된 `free_text` verdict나 로컬 체크리스트가 PG 승인 전이를 대신하지 않는다. 로그→scenario→실기기 관측→E2E 생성은 trace·환경·실제 effect와 assertion을 연결해야 하며, 연구 문서와 screenshot 지시만으로 완성되지 않는다. 삼성 기기 작업은 유예한다.

Astra의 처음 설계/마지막 검수, Sol의 중요 구현 및 Astra 동작 재현 가드레일, Terra의 단순 구현 및 Sol 동작 재현 자격은 사용자 요구다. 읽은 자료의 sonnet 명칭·top-K/토큰 예산·커리큘럼/critic 반복을 이 자격 증거로 세지 않는다. 같은 spec/환경/오라클과 오류 사례로 결과를 비교하고 사람 인수 경계를 지킨 뒤 모델 이전을 판단해야 한다. 이번 검토는 그 평가나 모델 호출을 수행하지 않았다.
