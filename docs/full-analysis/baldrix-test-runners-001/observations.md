# Actual original runner helper observations

The original compaction manual runner completed six tests with rc0. A separate component process imported the original runners and called their helpers on synthetic files, using real Python/pytest subprocesses and real scratch symlinks. No method, provider, subprocess result or clock was patched. Both executions used the existing immutable image, read-only pinned source, no network and bounded scratch/process resources. Raw streams and receipts remain authoritative for these observations; this is not a full upstream suite run or human acceptance.

- An empty Python file was rc0 directly and through `_run_subprocess`, with no output or assertions. A stderr FAIL marker was visible in the direct process but discarded by the helper on rc0. A stdout FAIL marker became helper rc1; explicit exit2 remained 2. SKIP-SUITE stayed rc0 with its marker for the caller to classify.
- Named fixture detection accepted an ordinary tmp_path test and a matching line inside a triple-quoted string. It missed a custom fixture, a class method and an async function. Invalid UTF-8 raised UnicodeDecodeError.
- Actual pytest was installed. Zero tests became helper rc1 and an ordinary assertion failure remained rc1. An assertion failure whose message contained `No module named pytest` became helper rc-1 with the dependency-missing message. This directly observes the helper's misclassification; the full run_all/run_units fallback and resulting acceptance were not executed.
- The original link helper created a POSIX symlink to a scratch target. Writing through it modified that target. Reset removed an ordinary state file while preserving the target write. Cleanup removed the temporary home but preserved the target and file. This demonstrates that the link is not a read-only boundary and credits the observed cleanup guard. No write through a source-tree link was attempted.
- Building an isolated home against the pinned source produced nine asset links and cleanup removed that home. This is the POSIX success path, not Windows junction or failure-fallback qualification.
- Calling the original compaction `_ok(False, ...)` returned None and added one failure to its list. No full pytest execution of a failing original compaction test was claimed. The original stdout oracle recognized a bracketed FAIL marker but not `ERROR 1` or an indented traceback line.

The full suites, installed hooks, child timeout/fall-through path, actual candidate push, collection-time state effects and host notification delivery were not executed. Missing assertions, synthetic statuses and passing original units do not establish SDD scenario acceptance. The unchanged 1,648-file source tree is checked by the execution wrapper and checkpoint verifier; Claude reviews the submitted records, not a separately observed execution.
