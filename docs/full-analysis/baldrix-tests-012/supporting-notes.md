# 직접 지원 구간의 판단

<a id="support-all"></a>

정확한 파일별 행 범위·원시 범위 SHA·전체 blob/SHA는 supporting-evidence.json에 결속한다. 지원 38개는 새 primary로 승격하지 않는다. 전부 이번에 읽은 범위이며 선행 전문 재사용 0이다. 검색 결과는 위치 탐색에만 사용했다. 69c8eb 출력에서 structural 중간이 잘렸으므로 해당 파일 63–292행을 4164a8에서 다시 읽었다. 나머지 미표시 구간은 읽었다고 계상하지 않는다. 원본 실행·import·collection·probe 0이다.

- **strike_research_consume**: 111–157은 디렉터리 존재 및 quota를 검사하고 dispatch를 먼저 기록한 뒤 payload를 반환한다. 실제 Agent spawn 영수증은 없다. 211–346은 fingerprint 경로 방어, prior event 기반 멱등, 위험 설정 변경 escalation, probe/gate 및 staging을 연결한다. prior consume는 artifact 내용 hash에 결속하지 않고, 낮은 우선순위 쓰기 생략도 staged=True다. candidate writer·probe 구현·원자성은 아직 닫지 않았다.
- **stub_faker_lint / stub_faker_gate**: Then 외와 pending은 면제다. unknown framework/no files는 indeterminate이지만 읽기 실패는 continue이므로 모든 파일 읽기 실패·step 추출 0의 분모를 따로 살펴야 한다. CLI 미식별 프로젝트는 PASS/0, indeterminate는 WARN/0이다. 문자열/delegate 존재는 실행 가능한 assertion과 다르다. overlay 실패 fallback도 실제 설정 배포 성공이 아니다.
- **stub_faker_mutation**: scratchpad의 결정적 clone 이름을 삭제 후 복제하고 baseline GREEN·시험 표식, mutant 실패 후 원복 GREEN을 요구한다. clone 삭제·shell runner·timeout·dependency는 이번 미독 구간에 남는다. 한 mutant CAUGHT에서 조기 반환하므로 전체 요구사항 검증이 아니다. finally clone 제거는 실제 격리나 동일 디렉터리 경합을 보장하지 않는다.
- **subagent_invocation_log**: record는 tools를 명시적으로 caller claim으로 저장한다. 읽기는 dict이면 필수 필드 없이 수용하고 깨진 JSON을 건너뛴다. search doc의 UTC 사전식 비교 계약은 파싱·세대 완전성 보장이 아니다. jsonl_append와 GC 등의 전체 구현은 이번 범위에서 미확인이다.
- **team_runtime**: psmux에 argv와 cwd를 전달하는 Windows 공백 경로 방어는 유지 후보다. session 존재·kill bool이 계약이며 모델 실행·결과 회수 증명은 없다. 동일 sid/worker 문자열과 psmux 세션 이름 검증은 위임되어 있다. 실제 psmux/프로세스 트리 종료·OS 호출은 미실행이다.
- **team_mailbox**: 커서는 행 번호다. yield 후 진행하고 finally에서 기록하므로 generator 중단 시 재전달이 가능하다. 잘못된 JSON·빈 줄은 커서를 넘기며 JSON scalar는 그대로 yield한다. 로그 잘림·교체·동시 독자·업무 처리 ACK를 묶는 거래가 없다. malformed 입력의 손실과 완료 승인 분모를 구분해야 한다.
- **team_worker_loop**: 전문에서 LLM을 호출하지 않는 echo worker임을 확인했다. task/query→echo, done→0, error→2, deadline→1, KeyboardInterrupt→130이다. 문서의 stdin EOF/SIGTERM graceful 약속과 달리 stdin 읽기나 SIGTERM handler가 없다. mailbox scalar는 msg.get 이전에 막지 않고, error outbox 전송 자체 실패도 바깥으로 전파될 수 있다. echo는 실제 자격 모델 협업 인수가 아니다.
- **team_policy / team_policy_check**: pure pass는 응답 수·viable capacity와 frozen 분모로 kill 제안을 만든다. 그러나 CLI 199행은 alive=False를 responded로 올린다. 210–225행에서는 terminate가 False 또는 예외여도 newly_killed에 추가하고 영구 killed 상태를 저장한다. 다음 pass에서 실제 살아 있는 worker가 제외될 수 있다. 정책 결정, 종료 요청, 종료 확인, 결과 수집을 별도 PG 상태로 관리해야 한다. quorum 함수·모든 관측 공급자·locking은 남아 있다.
- **subagent_refs / fix_subagent_refs**: refs main은 참조/agent 이름 비교 후 FAIL을 출력하고 None으로 끝난다. 없는 agents는 PASS/skip이고 telemetry 쓰기가 있다. fixer의 읽은 함수는 regex가 잡은 prefix/suffix를 보존하지만 실제 파일 저장·원자 쓰기·전체 참조 폐쇄는 미독이다. 이름 존재는 도구 가용성이나 모델 자격이 아니다.
- **subprocess_decode_guard**: SyntaxError는 빈 findings, 읽기 OSError도 건너뛴다. graduation/registry import 실패는 비차단으로 떨어지고 findings가 있어도 기본 WARN/0이다. encoding 키를 명시하는 정적 검사와 실제 자식 stdout/stderr의 디코딩 성공을 분리해야 한다. cp949 실패 설명은 원문의 과거 주장이다.
- **surgery**: branch·dirty 방어 뒤 headless 모델을 호출하고 전후 문자열을 평가한다. 실패 시 git checkout으로 되돌리며 실패를 기록하지만 run_ok=False 자체는 v.ok 판정의 필수 조건이 아니다. refresh 실패는 경고뿐이다. 동시 쓰기·모델이 바꾼 다른 파일·정확한 preimage·rollback 성공 및 승인 결속은 시험과 이 읽은 범위로 닫히지 않는다.
- **telemetry_read**: errors=ignore로 UTF-8 오류를 제거하고 JSON 값을 그대로 yield한다. dict가 아닌 값이면 count 함수의 get에서 예외가 날 수 있어 never raises 문구보다 실제 보장이 좁다. ACK는 텔레메트리가 비어도 먼저 로드하며 ts만 비교한다. 손상·누락은 성공으로 계산하지 않아야 한다.
- **telemetry_report / timefmt**: report 72행은 Z를 제거한 naive 시간을 mktime에 넘겨 UTC를 지역 시간으로 해석한다. 반면 timefmt 71–77행은 Z/z를 +00:00으로 바꿔 aware parsing한다. report의 오래된 이벤트 제거 시험은 이 차이를 놓친다. percentile은 인덱스 선택이며 정규 중앙값과 다르다. timefmt는 ValueError만 잡아 플랫폼별 timestamp 범위의 OSError/OverflowError까지 never raises를 보장하지 않는다. native OS 재현은 하지 않았다.
- **test validator**: 전문에서 파일 이름·문자열·보고서 디렉터리 존재만 본다. 빈 클래스·오래된 결과 디렉터리도 긍정 표식이 되며 Java service 이름 매칭은 실제 coverage가 아니다. FAIL 출력 후 main 반환값은 None이다. 실행 결과의 revision·시간·수집 수·assertion을 별도로 요구해야 한다.
- **test_depth**: AST 안의 모든 assert/raise, helper 이름 부분 일치, 문자열 [FAIL]을 깊이 신호로 인정한다. 실행 불가 분기나 단순 상수도 통과한다. 입력 없음/구문 오류는 findings가 없어 PASS로 보일 수 있고 오류 발견 시에도 WARN이다. 직접 run_units subprocess 경로는 stdout failure marker를 볼 수 있지만 pytest 경로에는 같은 사후 marker 검사 없이 pytest rc를 반환한다. 그러므로 어느 경로에서도 print가 assertion이라는 설명은 성립하지 않는다.
- **testgen**: 읽은 dispatch와 roundtrip은 ID 집합을 비교하며 duplicate를 제거한다. 따라서 ID 재사용 의미 변화·중복·retire·step 구현이 보장되지 않는다. 구체 템플릿과 parser/export writer는 이번 지원에서 전체를 읽지 않았다. 생성 스캐폴드와 검증 완료를 분리한다.
- **thin_skill_advisor**: bool 점수를 제외하는 방어는 있다. 전체 events를 list로 만든 다음 최근 N개를 자르므로 메모리/읽기가 완전히 bounded라는 문구는 부정확하다. max_events=0은 [-0:]로 전체가 남는다. 현재 full_skills 이름을 받는 prompt caller는 실제 연결되어 있지만 실패 시 침묵하고, context output 이후 소비/모델 행동은 미확인이다. 역사적 thin 분류는 정답 라벨이 있는 precision가 아니다.
- **threshold_registry_locked / threshold_registry**: 잠긴 집합 교집합을 출력 검사하고 proposer 및 apply에서 다시 검사한다. registry 다섯 항목 중 네 항목은 읽은 선언에 metric/guard dotted 경로가 없어서 proposer에서 건너뛴다. 이름 deny는 정책의 모든 쓰기 경로를 불변으로 만들지 않는다. 목록/등록은 자동 승인 근거가 아니다.
- **threshold_metrics / no_degradation_gate**: metric은 score>=threshold 중 score>threshold 비율이며 eligible=0이면 1.0이다. 실제 품질 정답이 없어 참 precision가 아니다. guard는 body_chars가 있는 일부 이벤트만 집계하며 일부 결측의 선택 편향이 남는다. 전체 결측 NaN과 불충분 holdout·비유한 결과 거절은 유지할 방어다. 시간 split은 문자열이며 후보 둘 중 holdout 개선 최대를 고르므로 holdout이 최종 후보 선택에도 사용된다. 독립 인수 세트는 아니다.
- **threshold_proposer / threshold_policy**: proposer의 telemetry_root 인자는 읽은 함수에서 소비하지 않는다. current는 적용 정책값 대신 registry.default다. ready JSON에는 suggested/current가 있지만 apply는 존재만 확인하고 값을 읽지 않는다. 제안값·revision·표본·승인자에 결속하지 않고 YAML write 후 flag unlink 실패를 무시한다. 병렬 replay·기록 실패가 원자적으로 닫히지 않는다. 잠긴 이름과 등록되지 않은 이름 거절은 유지하되 Zeus에서는 PG 거래와 Git 정책 정의, 독립 검증 및 명시 승인 영수증으로 변형해야 한다.
- **tier1_counts**: unknown과 명시 zero를 나누는 점은 유용하다. 첫 출력 매치를 쓰므로 다중 suite 합계·로그 prefix·가짜 출력에 취약하다. pytest 합계는 skip를 제외하고 실패/xfailed 등을 포함하지만 Baldrix는 전체 분모를 읽는다. 따라서 framework 사이 tests의 의미도 같지 않다. dict.ok는 선행 gate를 신뢰하며 그 생산·소비자는 이번에 닫지 않았다.
- **tech_stack / tech_stack_nudge / context_load**: YAML 부분 파서와 extension 문자열은 후보 경로만 만든다. 없음/읽기 실패/단일 common이면 None으로 광범위 후보 fallback이다. nudge는 파일 존재만 보고 cache의 미래/NaN timestamp가 오래 남을 수 있다. temp 경로는 TEMP/TMPDIR 또는 /tmp로 플랫폼에 의존하고 cache의 동시 변경은 별도다. context caller 연결은 읽었지만 경고 수신이나 실제 skill 적합성은 미확인이다.
- **agent_tool_audit / agent_invocation_audit / settings**: frontmatter가 없으면 빈 집합, 비교도 빈 결과다. 실제 플랫폼 권한과 self-report 모순의 구별을 추가로 해야 한다. hook은 Agent만 받고 subagent_type 없음은 건너뛰며 로그와 telemetry 양쪽 실패 시 침묵한다. settings에 Agent matcher와 절대 Windows 경로·timeout 5가 존재하지만 실제 설치/실행은 확인하지 않았다. 원문의 model·bypassPermissions 설정은 분석 데이터이고 Zeus 권한 지시가 아니다.
- **run_units / conftest**: fixture 이름 regex에 해당하면 pytest, 아니면 수동 main 경로가 갈린다. main 경로는 stdout marker를 검사하지만 pytest 경로는 rc만 본다. pytest 미설치는 skip 신호, collection0은 실패로 바꾸는 방어가 있다. conftest는 환경변수와 insight whitelist/cache를 바꾸고 stdin shim을 설치한다. 이미 import되어 값이 묶인 다른 모듈의 상수를 전부 복원하지 않는다. 자식 환경은 기존 env를 상속하므로 비밀정보/플러그인/OS 격리까지 성립하지 않는다. 원본 실행0이며 read 범위 밖의 runner 완료/통합 경로는 root의 별도 검토와 중복 승격하지 않는다.

위 경계는 모두 Zeus 8단계 SDD에서 요구 정의·설계·생성 제안·검증·사람 인수 및 운영 완료를 구분하는 변형 후보 판단이다. 실제 Zeus 코드와의 동등성 검증, PG 거래 구현, 모델 자격, 라이선스 원문 및 외부 링크 검증, Windows/Linux/WSL 실행, 실제 Claude의 전체 영역 검토·흡수 승인은 미완료다.
