# Original validator observations

Root read all four original unit modules in full after the independent source review.
structural (21), semantic (17), cross_ref (11) and boilerplate (12) list 61 tests total.
They invoke actual functions and temporary files using synthetic schemas, summaries,
evidence paths and claimed tool manifests. They check their classification contracts,
not historical fabrication, tool capabilities, actual model work or human acceptance.
Each main counts both assertion failures and other exceptions and returns nonzero on
failure. Hardcoded nonexistent paths are assumptions under the isolated environment.

All four original wrappers subsequently returned zero and reported those 61 tests passing
in the recorded immutable Docker image. A separate component program called original
methods with real isolated files and no method/clock/subprocess/provider patches. All
1,648 pinned source files remained byte-identical. No host credentials/network/live
harness or native Windows/WSL environment was involved.

The component output records these bounded observations:

- No checks, additionalProperties=false without properties, enum=[1] with bool True,
  bounded numeric NaN, nested missing evidence and absent tool manifest returned ok.
  The bool case deliberately has no integer type declaration: it does not claim that
  the explicit integer predicate accepts bool.
- NUL path raised ValueError and unhashable schema type raised TypeError.
- One matching file plus one missing file produced semantic CLEAN **with a retained
  missing-file error**. It is not an assertion that errors are absent from the result.
- Repeating one file path and one-readable/one-missing evidence both produced
  SUSPICIOUS_CHERRY_PICKED with one unique ratio. Two unrelated readable files produced
  consensus CLEAN at overlap zero. This is the cross-file function alone, not the whole
  hook decision: semantic.check can disagree with it.
- ASCII min_chars=1 still yielded no two-letter tokens; CJK min_chars=99 still yielded
  three bigrams. Neither observation measures actual language understanding.
- A 6,030-character file was strong suspicion with the default 4,096-byte head but CLEAN
  with max_file_bytes=-1, reading the full file. A small 20-byte boilerplate cap made the
  same long file likely boilerplate. Custom arguments were directly supplied; reachability
  of negative/custom values through the actual hook is not established.
- A synthetic LICENSE review target was classified boilerplate. The field name
  boilerplate_legitimate_license_target labels the constructed scenario, not an actual
  authenticated human task or proof that all such classifications are incorrect.
- Windows backslash basename matching on Linux returned false. Native Windows behavior
  and any cross-platform product failure were not executed here.

These runs corroborate specific mechanisms while leaving full producer/caller/config,
downstream grade consumption, actual OS/process behavior, license and human/model/adoption
evidence open. Claude's independent comparison is pending at this note's creation.
