# D-050 전문 검토: 사이클 재개방과 누적 실패 이력

원문: `harness-design` 커밋 `20147dde412c1f2d84178d5c3665157ced1e7334`, `design/decisions/D-050-autonomous-cycle-reopen-confirmed.md`. 전문을 읽었다. 이 기록은 문서의 주장과 설계 결정을 분석하며 해당 구현의 현재 실행 결과를 인증하지 않는다. 원문에 인용된 외부 제품의 수치와 역사적 실측은 이번 검토에서 재검증하지 않았다.

문서는 원인 진단의 네 차례 정정을 먼저 남긴다. 완료 후 재실행 스킵은 의도된 정책이고, 새 실행 경계 이벤트도 이미 있었다. 실제 완료 판정 호출 경로와 공유 단계 식별자, 서로 다른 후보의 실행이라는 조건을 다시 확인한 기록이다. Zeus에 가져올 경험은 이 특정 함수명을 그대로 쓰는 것이 아니라, 장애 티켓에 최초 가설·반증·정정된 호출 경로·입력 식별자를 보존하는 절차다.

설계는 현재 사이클의 상태와 누적 시도·실패 이력을 분리한다. `cycle_started.redo`는 완료 상태를 재개방하되 `attempts`를 지우지 않는다. 순수 도출기는 시계를 읽지 않고, 시간과 냉각 판단은 `circuit`에 둔다. 사람 관여 루프와 자율 루프의 도출은 공유하며 발급 주체를 구분한다. Zeus에서는 이 구분에 티켓 버전·실행 ID·검수 권한을 함께 결속해야 한다. 과거 성공을 새 사이클의 검증으로 승계하거나 반복 횟수를 곧 신뢰도로 승격해서는 안 된다.

문서 자체가 중요한 미구현 경계를 인정한다. 후보를 건너뛰는 정책은 후보를 폐기하는 정책이 아니지만, 기존 circuit은 후보별이 아니라 전체 스폰 게이트다. 따라서 문서의 후보별 건너뛰기를 이미 구현된 기능으로 흡수하면 안 된다. 대기 후보 수·건너뛴 이유·다음 재평가 시각을 로그와 사용자 화면에 남기는 동반 의무가 필요하다. 단순한 정상 heartbeat만으로 후보들이 계속 처리된다고 판단할 수 없다.

추가 잔여는 누적 attempts 소비자의 재시도 예산, failure ledger·gate ratchet·staleness의 수명, 컴팩션 후 pipeline 시작 정보 보존, 재장전 시 cycle 도출, 사람 화면과 기계 판정의 질문 차이다. 특히 “이 실행에서 완료”와 “과거에 한 번 완료”는 서로 다른 데이터다. 새로운 원장이나 이벤트를 더 만드는 작업에 앞서 기존 생산자·소비자·압축·화면의 동일 입력 대조가 필요하다.

현재 판정: 설계 경험의 **적응 후보**, 구현 흡수·독립 승인 미완료. 원문 전체 읽기는 완료했지만 연결된 구현/설정/테스트 전수 추적과 현재 실행 검증은 남아 있다. 이 파일은 전역 원장에서 `body_reviewed_call_test_trace_pending`으로 기록한다.
